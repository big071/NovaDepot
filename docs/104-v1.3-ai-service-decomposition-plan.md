# v1.3 Sprint Q2 AiService Decomposition Plan

> Status: ACT PLAN
> Sprint: v1.3 Q2
> Scope: backend AI module refactor only, with behavior preserved.

## Summary

Sprint Q2 decomposes `AiService` without changing public behavior. It is not an AI feature sprint.

Q2 must preserve:

- DeepSeek success and failure behavior.
- `AI_FALLBACK_ENABLED=false` explicit failure.
- `AI_PROVIDER=rule` direct RuleProvider behavior.
- Streaming event names and payload shapes.
- Stop generation behavior.
- Recent 20-round context behavior.
- Read-only Function Calling behavior.
- Tool cards and final structured answer shape.
- `ai_usage_logs` semantics.
- Existing `/api/v1/ai/**` routes, request shapes, response keys, permissions, and frontend behavior.

## Current Responsibilities

`AiService` currently owns too many responsibilities:

- Sync chat orchestration.
- Streaming and SSE event emission.
- Conversation create/list/archive/resolve.
- Message save/update/list/recent context.
- Prompt rendering and default prompt text.
- Provider name resolution and provider lookup.
- Provider failure payload construction and fallback handling.
- Manual/degradation usage logs.
- AI conversation audit writes.
- Small conversion helpers.

`AiFunctionCallingOrchestrator` already owns Function Calling context preparation, tool execution, tool limit behavior, no-result warnings, and final tool-backed answer composition. Q2 should not duplicate that service.

## Target Services

| Class | Responsibility |
|---|---|
| `AiProviderResolver` | Resolve provider name, enforce paid-disabled fallback to rule, find provider by scene, check DeepSeek provider names. |
| `AiPromptService` | Normalize scene, map knowledge scene, render DB prompt template or current built-in defaults. |
| `AiUsageLogService` | Save degradation/manual logs and list usage logs with the current response shape. |
| `AiAuditService` | Write AI audit logs without letting audit failures break chat. |
| `AiConversationService` | Create/list/archive/resolve conversations and scheduled inactive archive. |
| `AiMessageService` | Save/update/list messages, list by conversation number, and load recent context. |
| `AiChatService` | Own synchronous chat orchestration. |
| `AiStreamService` | Own streaming/SSE lifecycle and stop handling. |
| `AiService` | Remain as a thin facade for existing controllers. |

## Implementation Order

1. Add focused characterization tests for provider resolution and prompt rendering.
2. Extract provider resolution.
3. Extract prompt rendering.
4. Extract usage logs and audit writes.
5. Extract conversation and message persistence.
6. Move sync chat orchestration into `AiChatService`.
7. Move streaming/SSE orchestration into `AiStreamService`.
8. Keep Function Calling in `AiFunctionCallingOrchestrator`; only update call sites.

Each step must keep existing controllers and routes unchanged.

## Test Plan

Focused backend tests:

- Provider resolver default provider, provider hint, paid-disabled rule fallback, unsupported provider error, DeepSeek name detection.
- Prompt rendering for default scene, warehouse scene, SOP scene, enterprise scene, and DB template `{{question}}` replacement.
- Chat behavior for `AI_PROVIDER=rule`, DeepSeek failure without fallback, and tool-backed structured answer preservation.
- Conversation/message behavior for create, archive, message listing, by-conversation-no lookup, and recent context ordering.
- Streaming smoke for meta/token/done/error event preservation.
- Function Calling no-regression around read-only tools, max 5 calls, no-result warning, and final answer sections.

## Non-Goals

Q2 does not:

- Add AI features.
- Change DeepSeek request/response behavior.
- Change fallback semantics.
- Change prompt text.
- Change Function Calling tool logic, count, permissions, or SQL.
- Change frontend pages.
- Change API route, request, or response contracts.
- Change database schema or migrations.
- Change RBAC.
- Start RAG, vector database, multimodal, or v2.0 work.

## Acceptance

Q2 is complete when:

- `AiService` is a thin facade or small coordinator.
- Provider, prompt, usage log, conversation, message, sync chat, and stream concerns live in focused services.
- Focused backend tests and existing E2E AI tests pass.
- Full validation passes or any environment-only issue is documented.
- No public behavior, API, schema, permission, env var, or frontend behavior is changed.
