# NovaDepot v1.0 功能边界冻结

## 1. v1 定位

NovaDepot v1.0 定位为"单租户、本地 Docker 可运行的智能仓储管理 + 客服 + AI 助手一体化最小闭环交付版"。

目标用户：小团队（3-15 人），含仓库管理员、仓储运营、客服运营、管理员四种角色协同工作。

## 2. v1 已包含能力

### 2.1 仓储运营

| 能力 | 说明 |
|------|------|
| 库存总览 | 库存列表、库存明细、库存流水 |
| 低库存预警 | 库存低于安全线自动标记，支持阈值配置 |
| 入库管理 | 入库单创建、提交、审核、执行（过账） |
| 出库管理 | 出库单创建、提交、审核、发运 |
| 库存事务追踪 | 每笔库存变动记录来源单据类型与编号 |

### 2.2 客服与工单

| 能力 | 说明 |
|------|------|
| 客服会话 | 多会话管理、消息列表 |
| AI 自动/建议回复 | 基于 FAQ/规则的候选回复与自动回复 |
| 工单管理 | 工单创建、状态流转、责任人指派、备注 |
| 工单处理历史 | 时间线查看状态变更、责任人变更、备注记录 |
| 工单沉淀知识 | 从工单生成 FAQ 草稿、SOP 草稿 |

### 2.3 知识库（FAQ / SOP / 规则配置）

| 能力 | 说明 |
|------|------|
| FAQ 维护 | 新增、编辑、启用、停用、草稿→确认 |
| SOP 维护 | 新增、编辑、启用、停用、草稿→确认 |
| 规则配置 | 管理员可修改业务规则（低库存阈值等），非管理员只读 |
| 知识引用 | AI 助手与客服回复展示 FAQ/SOP/规则引用来源 |

### 2.4 AI 助手

| 能力 | 说明 |
|------|------|
| AI 对话 | 企业级 AI 助手对话界面 |
| 意图识别 | 任务型问题自动识别并触发 Agent 执行 |
| 知识引用 | 回答中展示命中的 FAQ/SOP/规则依据 |

### 2.5 Agent 中心

| 能力 | 说明 |
|------|------|
| Agent 任务执行 | 低库存分析、补货建议、异常巡检 |
| 业务化结果展示 | 摘要卡片 + 表格明细 + 执行依据 + 建议动作 |
| 历史记录 | Agent 执行历史查询与回看 |

### 2.6 审计中心

| 能力 | 说明 |
|------|------|
| 操作审计 | 知识变更、单据操作、客服操作均记录审计日志 |
| 多维筛选 | 按模块、动作、资源类型、操作人筛选 |
| 权限审计 | 仅管理员可访问审计中心 |

### 2.7 角色权限（RBAC）

| 能力 | 说明 |
|------|------|
| 4 角色体系 | admin（管理员）、warehouse（仓储运营）、cs（客服运营）、observer（观察员） |
| 页面级权限 | 路由守卫根据角色控制页面访问 |
| 操作级权限 | 按钮/输入框根据权限禁用或隐藏 |
| 统一 403 | 越权访问返回统一 403 提示页面 |

### 2.8 基础设施

| 能力 | 说明 |
|------|------|
| Docker 部署 | 单命令 `docker compose up` 启动全部服务 |
| 数据初始化 | SQL 种子数据 + `reset-commercial-baseline.ps1` |
| 数据质量检查 | `data-quality-check.ps1` 自动化检查 |
| E2E 自动化测试 | 10 条 Playwright 用例，覆盖主链路与失败路径 |

## 3. v1 明确不包含

以下能力不在 v1.0 范围内，保留到后续版本：

### 3.1 暂不包含

| 不包含 | 原因 |
|--------|------|
| 多租户正式版 | 当前阶段单租户架构优先验证业务闭环 |
| 计费系统 | 尚未进入商业化运营阶段 |
| 完整 ERP 三链（采购/销售/财务） | 先做 WMS 核心，ERP 后续按需扩展 |
| RAG / 向量数据库 | 当前规模下 FAQ/SOP 规则匹配已足够 |
| 复杂工作流引擎（BPM） | 单据状态机 + 审核已满足当前需求 |
| 知识图谱 | 过于复杂，ROI 不足以在当前阶段投入 |
| DeepSeek 强依赖 | AI 层保持 Mock + Rule 优先，避免付费模型硬绑定 |
| 移动端 App | 先做桌面端 Web |

### 3.2 技术债务（已知但暂不修复）

| 项目 | 说明 |
|------|------|
| `docs/00-overview.md` 技术路线 | 文档中仍写 Next.js，实际已是 Vue 3。本次 v1 收口已更新。 |
| 前端部分旧组件命名 | 不影响功能，后续统一规范即可 |
| 后端部分 DTO 未完全独立 | 当前复用 Entity，不影响运行 |

---

## 4. v1 边界原则

1. **单租户优先**：所有数据无租户隔离概念
2. **Mock AI 优先**：AI Provider 抽象层已就绪，当前使用 Mock + Rule Provider，可在不修改业务代码的前提下切换到付费 Provider
3. **本地 Docker 一键启动**：开发者/评审者无需配置复杂环境
4. **只做闭环不做大而全**：每个模块有完整的"创建→使用→审计"链路
5. **权限始终在线**：所有页面和 API 均受 RBAC 控制
