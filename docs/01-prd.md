# NovaDepot PRD（执行版）

## 1. 项目背景
NovaDepot 面向中小企业，解决“仓储、进销存、客服、内部协同”系统分散的问题。项目定位为“智能仓库管理系统 + 轻 ERP + 智能助手 + 智能客服”，强调实用、可落地、可商用。

技术与部署约束（强制）：

| 类别 | 约束 |
|---|---|
| 后端 | Java 17+、Spring Boot 3、MyBatis-Plus、Maven |
| 数据层 | MySQL 8、Redis |
| 前端 | Next.js + TypeScript + Tailwind + shadcn/ui |
| 接口文档 | SpringDoc OpenAPI / Swagger |
| 部署 | Docker 镜像 + Docker Compose 编排 |
| 配置 | `application.yml` + `application-dev.yml` + `application-docker.yml` |

## 2. 产品目标
本项目目标不是重型 ERP，而是建立中小企业可直接使用的完整闭环。

| 目标方向 | 目标说明 | 量化指标（建议） |
|---|---|---|
| 仓储准确性 | 库存、流水、单据一致 | 账实准确率 >= 98% |
| 作业效率 | 入库、出库、盘点流程标准化 | 关键操作耗时下降 >= 30% |
| 业务闭环 | 采购-入库-库存-销售-出库-客服闭环 | 核心链路可追溯率 100% |
| 可商用性 | 多租户、审计、通知、导入导出可扩展 | 新租户开通 < 30 分钟（商用阶段） |
| AI 演进 | 前期免费 AI，后期付费 API 可切换 | 业务层 0 改造切换 Provider |

## 7. 核心业务流程说明
| 流程 | 步骤 | 关键控制点 |
|---|---|---|
| 采购入库 | 采购单 -> 到货 -> 入库单 -> 上架 -> 库存增加 | 审批、质检、流水落库 |
| 销售出库 | 销售单 -> 锁库 -> 拣货复核 -> 出库 -> 库存扣减 | 锁库校验、复核、出库确认 |
| 调拨 | 调出单 -> 调入确认 -> 库存迁移 | 调出调入一致性 |
| 盘点 | 盘点任务 -> 差异复核 -> 调整单 | 差异审批与审计 |
| 客服闭环 | 咨询 -> FAQ/建议回复 -> 工单 -> 归档知识 | SLA、知识沉淀 |

## 11. 列表页/详情页/创建页/编辑页通用交互规范
| 页面类型 | 交互规范 |
|---|---|
| 列表页 | 固定筛选区（状态/时间/关键字）、分页、列设置、批量操作、导出 |
| 详情页 | 顶部状态条、基础信息卡片、明细表、操作日志、审批记录 |
| 创建页 | 分步或单页表单、必填标识、即时校验、草稿保存 |
| 编辑页 | 乐观锁版本控制、防并发覆盖、变更摘要提示 |

通用规则：
- 所有关键操作需二次确认（提交、审核、作废、出库确认）。
- 列表页支持“最近筛选记忆”。
- 状态色统一：草稿灰、处理中蓝、完成绿、异常红、作废深灰。

## 12. 状态流转设计
| 单据 | 状态流转 |
|---|---|
| 入库单 | DRAFT -> SUBMITTED -> APPROVED -> RECEIVING -> COMPLETED / CANCELED |
| 出库单 | DRAFT -> SUBMITTED -> APPROVED -> PICKING -> REVIEWING -> SHIPPED / CANCELED |
| 调拨单 | DRAFT -> SUBMITTED -> APPROVED -> TRANSFERRING -> COMPLETED / CANCELED |
| 盘点单 | DRAFT -> IN_PROGRESS -> DIFF_PENDING -> APPROVED -> ADJUSTED / CANCELED |
| 工单 | OPEN -> PROCESSING -> WAITING_USER -> RESOLVED -> CLOSED |

约束：
- 禁止跨级跳转状态。
- 状态变更必须记录审计日志。
- 核心状态变更通过事务 + Redis 锁保护。

## 17. AI 助手设计
核心要求：开发阶段免费可用，商用阶段可无缝切换付费模型。

| 层级 | 设计 |
|---|---|
| 接口层 | `AIProvider` 统一接口，业务只调用编排器 |
| MVP Provider | MockProvider、RuleProvider、TemplateProvider |
| 商用 Provider | PaidLLMProvider（按配置启用） |
| 路由层 | AIOrchestrator 按场景路由（仓储/经营/客服） |
| 安全层 | 权限校验、敏感信息过滤、输出审查 |

建议开关：
- `ai.paid.enabled=false`（MVP）
- `ai.provider.default=mock`
- `ai.route.wms=rule`
- `ai.route.cs=template`

## 19. 权限模型建议
| 维度 | 建议 |
|---|---|
| 鉴权框架 | Spring Security + JWT |
