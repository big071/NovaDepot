# NovaDepot v1.0 核心业务流程

## 1. 入库流程

```
仓储运营              管理员                系统
  │                    │                    │
  │  1. 创建入库单     │                    │
  │  (选择产品、数量、  │                    │
  │   库位、批次)      │                    │
  │ ──────────────────────────────────────→│ 生成入库单（待提交）
  │                    │                    │
  │  2. 提交入库单     │                    │
  │ ──────────────────────────────────────→│ 状态 → 待审核
  │                    │                    │
  │                    │  3. 审核通过/驳回  │
  │                    │ ─────────────────→│ 通过 → 待执行
  │                    │                    │ 驳回 → 已驳回（退回提交人）
  │                    │                    │
  │  4. 执行入库       │                    │
  │  (确认实物入库)    │                    │
  │ ──────────────────────────────────────→│ 状态 → 已完成
  │                    │                    │ 库存增加 + 事务记录
  │                    │                    │ 审计日志记录
```

### 状态流转

`待提交` → `待审核` → `待执行` → `已完成`
`待审核` → `已驳回`（审核不通过）
`待提交` / `已驳回` → `已取消`

### 关键约束
- 创建人与审核人不能是同一人
- 审核通过后，库存 **不立即增加**，仅状态变更
- 执行完成后，库存 **实际增加**
- 每步操作记录审计日志

## 2. 出库流程

```
仓储运营              管理员                系统
  │                    │                    │
  │  1. 创建出库单     │                    │
  │  (选择产品、数量、  │                    │
  │   客户信息)        │                    │
  │ ──────────────────────────────────────→│ 生成出库单（待提交）
  │                    │                    │
  │  2. 提交出库单     │                    │
  │ ──────────────────────────────────────→│ 状态 → 待审核
  │                    │                    │
  │                    │  3. 审核通过/驳回  │
  │                    │ ─────────────────→│ 通过 → 待发运
  │                    │                    │ 驳回 → 已驳回
  │                    │                    │
  │  4. 发运出库       │                    │
  │  (确认实物发出)    │                    │
  │ ──────────────────────────────────────→│ 检查库存是否足够
  │                    │                    │ 足够：库存减少 + 事务记录
  │                    │                    │ 不足：报错，提示库存不足
```

### 状态流转

`待提交` → `待审核` → `待发运` → `已完成`
`待审核` → `已驳回`
`待发运` → `库存不足`（发运失败，状态不变）

### 关键约束
- 发运执行时校验库存，库存不足则 **拒绝发运并提示错误**
- 审核人必须为管理员角色

---

## 3. 库存与低库存巡检

```
库存数据
  │
  ├── 实时库存总览页
  │   按产品/库位展示当前库存量
  │   低于安全线的标红预警
  │
  └── 库存事务流水
      每笔出入库操作生成事务记录
      来源可追溯（单据类型 + 单据编号）
```

### 低库存阈值

可在规则配置中调整（仅管理员可修改）：
- `low_stock_threshold`：默认 50 单位
- `critical_stock_threshold`：默认 10 单位

## 4. 客服工单流程

```
客户（模拟）          客服运营                 系统
  │                    │                       │
  │  1. 发送咨询消息   │                       │
  │ ──────────────────→│                       │
  │                    │  2. 查看消息          │
  │                    │  AI 自动建议回复      │
  │                    │  (命中FAQ/SOP/规则)   │
  │                    │                       │
  │                    │  3. 人工发送回复      │
  │                    │ ─────────────────────→│ 消息发送，记录会话
  │                    │                       │
  │                    │  4. 如需进阶处理      │
  │                    │  创建工单              │
  │                    │ ─────────────────────→│ 工单创建
  │                    │                       │
  │                    │  5. 处理工单          │
  │                    │  (回复、备注、转派)   │ 状态更新 + 历史记录
  │                    │                       │
  │                    │  6. 关闭工单          │
  │                    │ ─────────────────────→│ 工单 → 已关闭
  │                    │                       │
  │                    │  7. 沉淀知识（可选）  │
  │                    │  工单 → FAQ 草稿      │
  │                    │  工单 → SOP 草稿      │
  │                    │ ─────────────────────→│ 生成草稿待确认
```

### AI 回复链路

```
客户消息到达
  → 提取关键词与意图
  → 匹配 FAQ（问题字段 + 关键字）
  → 匹配 SOP（适用场景 + 关键步骤）
  → 匹配规则（优先级、分类、阈值）
  → 生成候选回复（含引用来源）
  → 自动填充到客服回复框（建议模式）
  或自动发送（需开启自动模式）
```

## 5. AI 助手使用流程

```
用户
  │
  │  1. 输入问题
  │  "优先补货顺序是什么？"
  │ ────────────────────────→
  │
  │  2. 系统处理
  │  ├── 意图识别（任务型/知识型/开放型）
  │  ├── 匹配 FAQ/SOP/规则
  │  ├── 若为任务型（如补货分析），触发 Agent
  │  └── 生成回复（含引用来源）
  │
  │  3. 查看回复
  │ ←────────────────────────
  │  回复中包含：
  │  - 结论描述
  │  - 引用来源（FAQ ID / SOP ID / 规则名称）
  │  - 建议下一步操作
  │
  │  4. 追问/对话
  │ ────────────────────────→
```

### AI 意图分类

| 意图类型 | 用户示例 | 处理方式 | 是否触发 Agent |
|----------|---------|---------|:-----------:|
| 任务型 | "补货建议"、"巡检异常"、"生成日报" | Agent 执行 | ✅ |
| 知识型 | "什么是标准入库流程"、"如何处理损坏商品" | 匹配 FAQ/SOP | ❌ |
| 开放型 | "今天仓库整体运行情况"、"有什么我需要注意的吗" | 通用业务回答 | ❌ |

## 6. Agent 执行流程

```
用户通过 AI 助手触发 / 手动触发
  │
  ▼
Agent 接收任务
  │
  ├── 低库存分析：查询库存数据 → 按安全线对比 → 按紧急度排序
  ├── 补货建议：基于低库存 + 历史消耗 → 生成补货建议量
  └── 异常巡检：扫描库存、单据、会话 → 标记异常项
  │
  ▼
生成结果
  ├── 摘要卡片（关键数字 + 结论）
  ├── 表格明细（逐项数据）
  ├── 执行依据（使用了哪些规则/数据）
  └── 建议动作（补货量、优先级、复查项）
  │
  ▼
记录 Agent 执行历史（可回看）
记录审计日志
```

## 7. 知识沉淀闭环

```
工单处理完成
  │
  ├── 客服点击"沉淀为 FAQ"
  │   → 自动填充：问题（来自客户消息）、场景、优先级
  │   → 人工编辑回复内容
  │   → 保存为 FAQ 草稿
  │   → 管理员或客服确认 → 正式生效
  │
  └── 客服点击"沉淀为 SOP"
      → 自动填充：主题、适用场景、标准步骤（来自操作记录）
      → 人工补充风险点、复核项
      → 保存为 SOP 草稿
      → 确认 → 正式生效
```

### FAQ/SOP 生命周期

```
[草稿] ──确认──→ [已启用] ──停用──→ [已停用]
  │                  │
  │ 继续编辑         │ 重新启用
  └──────────────────┘
```

所有知识变更（新增/编辑/启用/停用）均记录审计日志。

## 8. 审核分离原则

| 操作 | 执行人 | 审核人 | 说明 |
|------|--------|--------|------|
| 入库审核 | 仓储运营创建 | 管理员审核 | 创建人与审核人必须不同 |
| 出库审核 | 仓储运营创建 | 管理员审核 | 防止自建自审 |
| 规则修改 | 管理员 | — | 无需审核，但记录审计 |
| FAQ/SOP 发布 | 客服/管理员 | — | 草稿→确认，记录审计 |

## 9. 审计覆盖

以下操作均自动记录审计日志：

| 模块 | 审计事件 |
|------|---------|
| 入库 | 创建、提交、审核、执行、取消 |
| 出库 | 创建、提交、审核、发运、取消 |
| 库存 | 调整、事务变更 |
| 客服 | 会话创建、消息发送、工单创建/变更/关闭 |
| FAQ | 新增、编辑、启用、停用、确认 |
| SOP | 新增、编辑、启用、停用、确认 |
| 规则 | 修改 |
| 用户 | 更新、角色变更 |
| Agent | 任务执行 |

每条审计日志包含：时间、操作人、模块、动作、资源类型、资源 ID、变更前/变更后 JSON。
