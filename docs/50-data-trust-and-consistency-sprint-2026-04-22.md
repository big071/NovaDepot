# NovaDepot 数据可信度与业务一致性增强 Sprint（2026-04-22）

## 1. 目标
让系统中的数据不仅“非空”，而且“可信、可解释、可复盘、可验证”。

## 2. 边界
1. 不新增无关模块，不重做整体架构。
2. 保持单租户本地 Docker 运行方式不变。
3. 改动集中在样本数据、口径一致性、页面说明、抽检脚本。

## 3. 当前问题摘要
1. 部分样本仍偏工程化命名（压测样本、部分编码字段）。
2. 低库存口径存在“固定阈值”和“安全库存语义”割裂风险。
3. 发布检查偏“接口可用性”，缺少“指标与明细一致性”校验。
4. AI 输出与业务事实虽然可用，但“依据说明”不够显式。
5. 审计中心和用户管理默认视图对新手偏复杂。

## 4. 本轮执行范围
1. 业务样本可信度增强：
   1. 优化商品、仓库、库位、库存、单据、工单、FAQ、AI 样本中的占位与工程化表达。
   2. 补充可解释的字段含义（尤其 remark/spec/content）。
2. 数据一致性强化：
   1. 仪表盘统计 vs 单据数据；
   2. 库存数量 vs 入出库流转；
   3. 低库存预警 vs 安全库存语义；
   4. 工单状态 vs 会话与责任人；
   5. AI 建议 vs 真实库存与单据事实。
3. 数据解释能力：
   1. 仪表盘指标口径说明；
   2. 低库存判断口径说明；
   3. 工单优先级说明；
   4. AI 建议依据说明。
4. 样本抽检与校验脚本：
   1. 新增最小可用抽检脚本；
   2. 演示前快速验证乱码、空关键数据、指标一致性、低库存一致性。
5. 新手模式补强（并入本轮）：
   1. 审计中心与用户管理支持“新手模式视图”；
   2. 入库/出库增加 Step 1/2/3/4 可视化步骤条；
   3. 首页增加角色化引导卡并支持一键切换推荐入口。

## 5. 核心口径定义
1. 仪表盘：
   1. `todayInbound`：今日创建的入库单数量；
   2. `todayOutbound`：今日创建的出库单数量；
   3. `lowStockCount`：库存记录中 `availableQty <= effectiveSafetyStock` 的数量。
2. 有效安全库存（`effectiveSafetyStock`）：
   1. 优先从商品 `spec` 文本解析“安全库存=数字”；
   2. 若无法解析，使用默认阈值 `10`。
3. AI 建议依据：
   1. 建议需引用真实 SKU / 库存状态 / 单据事实；
   2. 若仅能给规则化建议，应明确“依据口径与阈值”。

## 6. 验收标准
1. 样本数据可读且业务语义可信，明显减少占位表达。
2. 仪表盘、库存预警、AI 低库存分析口径一致。
3. 数据抽检脚本可在演示前一键运行并输出关键检查结果。
4. 页面含口径说明，降低数据误解风险。
5. 新手模式视图可用，且不影响原有高级能力。
6. Docker 本地可运行，主链路无回归。

## 7. 执行与验证步骤
1. 重置样本：`./scripts/ops/reset-commercial-baseline.ps1`
2. 运行发布检查：`./scripts/ops/release-checklist.ps1`
3. 运行数据抽检：`./scripts/ops/data-quality-check.ps1`
4. 页面人工验收：
   1. 仪表盘口径说明与角色引导；
   2. 入库/出库步骤条与状态提示；
   3. 库存低库存口径说明；
   4. 客服优先级说明；
   5. AI 依据说明；
   6. 审计/用户新手模式视图。
