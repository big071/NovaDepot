# NovaDepot 角色化体验 + 审计中心优化 + AI/Agent 打通 + 新手引导 + 智能客服增强 Sprint（2026-04-23）

## 1. 目标与边界
1. 目标：在当前商用阶段基线下，完成角色化体验、审计中心易用性、AI/Agent 一体化、Agent 参数可解释、新手引导落地、客服 AI 辅助增强。
2. 边界：
   1. 不扩展多租户。
   2. 不扩展计费体系。
   3. 不进行无关大重构。
   4. 保持 Docker 本地可运行。

## 2. 本轮差距清单（开始前）
1. 菜单和首页主要按统一视图展示，角色差异不明显。
2. 登录页直接暴露技术账号字段，演示入口不友好。
3. 审计中心筛选维度与交互偏技术化，业务用户理解成本高。
4. AI 助手与 Agent Center 独立，任务型意图无法直接形成 Agent 任务闭环。
5. Agent 参数区是固定调试式输入，不随任务变化。
6. 新手引导虽有局部文案，但首次登录和页面级“下一步建议”还不完整。
7. 客服 AI 辅助能力分散，缺少发送前可用建议面板。

## 3. 本轮执行范围
1. 角色化体验：
   1. 菜单按角色分组展示。
   2. 首页内容与快捷入口按角色聚焦。
   3. 页面级无权限说明页（替代纯 403 提示）。
2. 登录体验：
   1. 中文业务角色展示。
   2. 演示账号快捷登录入口。
3. 审计中心优化：
   1. 筛选控件支持可选、可搜索、可清空。
   2. 增加时间范围、业务编号、仅失败筛选。
   3. 详情展示字段中文化与变更前后可读化。
4. AI/Agent 打通：
   1. 识别任务型意图并路由 Agent。
   2. 返回执行步骤、执行依据、执行结果。
   3. 同步写入 Agent 历史并在 AI 页面可查看。
5. Agent 参数解释：
   1. 按任务动态展示参数。
   2. 参数中文标签、用途说明。
   3. 执行前说明（做什么/读什么/产出什么）。
6. 新手引导与客服增强：
   1. 首页和重点页面补齐引导提示。
   2. 首次登录最小引导。
   3. 客服工作台增加 FAQ 命中、候选回复、工单分类与优先级、SOP 建议。
7. DeepSeek 预留：
   1. 预留 Provider 与配置。
   2. 默认关闭，不依赖付费 API。

## 4. 角色化口径
1. `admin`：经营总览、审计、用户管理、AI/Agent。
2. `warehouse_manager`：库存、入库、出库、低库存。
3. `operator`：待处理草稿、作业入口。
4. `cs_agent`：会话、工单、FAQ、客服 AI 建议。
5. `viewer`：只读总览与建议。

## 5. AI 任务意图与 Agent 映射
1. 低库存分析 -> `LOW_STOCK_ANALYSIS`
2. 补货建议 -> `REPLENISH_SUGGESTION`
3. 异常巡检 -> `ANOMALY_PATROL`
4. 运营日报 -> `DAILY_OPERATIONS_REPORT`
5. 工单处理建议 -> `CS_TICKET_TRIAGE`
6. SOP 建议 -> `SOP_RECOMMENDATION`

识别为任务型请求后：
1. AI 服务创建/复用会话。
2. 调用 Agent 执行并记录 run。
3. AI 响应包含：任务类型、步骤摘要、执行依据、结果摘要、runId。
4. run 同时可在 Agent Center 历史中查询。

## 6. Agent 参数可解释口径
1. 仅展示当前任务需要的参数。
2. 参数示例：
   1. 建议输出条数。
   2. 近几天出库趋势。
   3. 巡检窗口天数。
   4. 日报日期。
3. 每项参数包含中文标签与用途说明。
4. 执行前展示任务说明：
   1. 会做什么。
   2. 会读取哪些数据。
   3. 输出什么结果。

## 7. DeepSeek 接入预留说明（默认关闭）
1. 新增配置项（默认关闭）：
   1. `app.ai.deepseek.enabled=false`
   2. `app.ai.deepseek.base-url=`
   3. `app.ai.deepseek.api-key=`
   4. `app.ai.deepseek.chat-model=deepseek-chat`
   5. `app.ai.deepseek.reasoner-model=deepseek-reasoner`
2. Provider 切换策略：
   1. 默认 `rule`。
   2. 开启后可通过 `providerHint` 指定 `deepseek-chat` 或 `deepseek-reasoner`。
   3. 当 deepseek 不可用时，回退 `rule/mock`，保证免费模式可运行。
3. 场景建议：
   1. `deepseek-chat`：客服回复润色、运营摘要、面向业务用户的自然语言输出。
   2. `deepseek-reasoner`：复杂异常归因、多条件策略比较、跨指标推理分析。

## 8. 本轮验收标准
1. 五类角色菜单、首页、快捷入口差异化明确。
2. 登录页中文业务角色+演示账号快捷入口可用。
3. 审计中心筛选增强和详情可读化可用。
4. AI 任务意图可路由 Agent，并在 AI 与 Agent 历史双端可见。
5. Agent 参数区不再是固定调试面板，改为业务任务表单。
6. 首次登录引导和重点页面引导可见。
7. 客服发送前可查看 AI 建议（FAQ/回复/分类/优先级/SOP）。
8. RuleProvider/MockProvider 保持可运行，DeepSeek 默认关闭。

## 9. 风险与回滚
1. 风险：角色菜单过严导致误拦截。
2. 控制：采用“权限点 + 角色映射”双校验，保留无权限说明页引导。
3. 风险：AI 任务路由误判。
4. 控制：仅对高置信关键词触发任务路由，其他请求走普通 AI 对话。
5. 回滚：
   1. 前端可回滚到统一菜单和固定参数表单。
   2. 后端可关闭 AI->Agent 路由逻辑并保留原聊天链路。
