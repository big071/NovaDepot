## 1. Context & Entry Gate

v1.1 has been released. DeepSeek is currently a placeholder provider returning mock text. Sprint 1 connects DeepSeek's real API, making it the default AI engine, while keeping `RuleAiProvider` as keyword degradation path and `MockAiProvider` as final fallback.

Current state (after v1.1):
- `DeepSeekChatAiProvider`: returns `[DeepSeek-Chat 接入预留]` mock reply
- `DeepSeekReasonerAiProvider`: returns `[DeepSeek-Reasoner 接入预留]` mock reply
- `Application.yml`: `app.ai.deepseek.*` config exists with env vars, `enabled` defaults to `false`
- `AiService`: provider routing & fallback chain working; `POST /api/v1/ai/chat` → provider resolution → prompt template → save message
- Frontend `AiAssistantPage.vue`: sends `POST /api/v1/ai/chat` with `providerHint: "deepseek-chat"`; renders reply as plain text; no streaming

## 2. Sprint Goal

Replace DeepSeek placeholder with real HTTP API calls, inject system prompts per scene, make `deepseek-chat` the default provider, keep `rule` as keyword degradation and `mock` as final fallback, and log every AI call with token/money cost for auditability.

## 7. Database Tables

### 7.1 New: `ai_usage_logs`

```sql
CREATE TABLE ai_usage_logs (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    tenant_id BIGINT NOT NULL DEFAULT 0,
    conversation_id BIGINT,
    provider VARCHAR(32) NOT NULL COMMENT 'deepseek-chat/deepseek-reasoner/rule/mock/paid',
    model VARCHAR(64) COMMENT 'deepseek-chat/deepseek-reasoner',
    scene VARCHAR(32) COMMENT 'warehouse/sop/enterprise',
    role VARCHAR(16) COMMENT 'system/user/assistant',
    prompt_tokens INT DEFAULT 0,
    completion_tokens INT DEFAULT 0,
    total_tokens INT DEFAULT 0,
    latency_ms INT DEFAULT 0,
    success TINYINT(1) NOT NULL DEFAULT 1,
    error_code VARCHAR(32),
    error_message VARCHAR(512),
    cost_estimate DECIMAL(10,6) DEFAULT 0 COMMENT 'estimated cost in CNY',
    created_by BIGINT,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_tenant_created (tenant_id, created_at),
    INDEX idx_provider (provider),
    INDEX idx_conversation (conversation_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='AI usage log';
```

## 11. Provider Degradation Chain

```
DeepSeekChatAiProvider (enabled? api-key present? API reachable?)
    ↓ on error/timeout/disabled
RuleAiProvider (keyword matching: stock, SOP, daily report)
    ↓ on error
MockAiProvider (echo reply, always available)
```

Degradation triggers:
1. DeepSeek API returns 4xx/5xx
2. API timeout (connect 5s, read 30s)
3. API key not configured or empty
4. `deepseek.enabled=false`

When degradation occurs:
- `AiService` catches exception, logs warning, writes `ai_usage_logs` with `success=0, error_code=AI_DEGRADED`
- Falls back to `RuleAiProvider` (keyword rules)
- If `RuleAiProvider` also fails, falls back to `MockAiProvider`
- Response includes `fallbackFrom` field so frontend can show degradation notice

## 13. Rollback Strategy

- **Code**: Revert `develop/v1.2-sprint1` merge; keep `main` at v1.1.
- **Config**: Set `AI_PROVIDER=rule` → all AI calls use RuleAiProvider (current v1.1 behavior).
- **DB**: `ai_usage_logs` table has no foreign keys; can be truncated or left as-is.
- **Frontend**: Hide `/settings/ai` route via permission; `/ai/enterprise` degrades gracefully via existing `fallbackFrom` field.
- **No impact on v1.1 paths**: WMS, ERP, CS, Agent, knowledge, audit, RBAC — all unchanged.

## 14. Acceptance Criteria

1. **DeepSeek API real call**: When valid `AI_DEEPSEEK_API_KEY` is set, `POST /api/v1/ai/chat` with `providerHint=deepseek-chat` returns a real DeepSeek-generated reply (not placeholder text).
2. **System Prompt injected**: Reply reflects the scene-specific system prompt (warehouse/sop/enterprise).
3. **Provider switch**: Setting `AI_PROVIDER=rule` makes all AI calls use RuleProvider; setting `AI_PROVIDER=deepseek-chat` uses DeepSeek.
4. **Degradation chain**: If DeepSeek API fails (no key, timeout, error), calls degrade to RuleProvider → MockProvider without throwing 500.
5. **Usage logs**: Every AI call writes one row to `ai_usage_logs` with provider, model, tokens, latency, success/failure.
6. **API key masked**: `GET /api/v1/ai/config` returns masked API key (e.g., `sk-xxxx...xxxx`).
7. **Permissions enforced**: Non-admin users get 403 on AI config and usage log APIs.
8. **v1.1 no regression**: Existing WMS inbound/outbound/inventory, ERP partners/purchases/sales/finance/stocktake, CS sessions, Agent tasks, knowledge base, RBAC, audit center — all unchanged.
