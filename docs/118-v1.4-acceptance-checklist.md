# NovaDepot v1.4 Acceptance Checklist

## Git State

- [ ] Current branch is `develop/v1.4` before release-doc commit.
- [ ] Working tree is clean before final merge to `main`.
- [ ] `v1.4` tag does not already exist before tag creation.

## Secret Scan

- [ ] No `.env` files are tracked or staged.
- [ ] No real API key, JWT secret, database password, private key, or access token is staged.
- [ ] No `node_modules`, `dist`, `target`, `test-results`, or `tmp` output is staged.

## Final Gate

- [ ] `docker compose up -d mysql redis backend frontend-vue`
- [ ] `./scripts/ops/reset-commercial-baseline.ps1`
- [ ] `./scripts/ops/data-quality-check.ps1`
- [ ] `cd backend && mvn test`
- [ ] `cd frontend-vue && npm run typecheck`
- [ ] `cd frontend-vue && npm run build`
- [ ] `cd frontend-vue && npm run test:unit`
- [ ] `cd frontend-vue && npm run test:e2e`
- [ ] `git diff --check`

## Functional Acceptance

- [ ] Role management supports create, permission assignment, detail readback, edit, and audit readback.
- [ ] Non-admin users cannot access role management.
- [ ] Built-in roles are not deleted or weakened.
- [ ] `warehouse01`, `cs01`, and `observer01` do not receive `ROLE_MANAGE`.
- [ ] Redis caches only stable reference data and evicts after write/import paths.
- [ ] Redis failure falls back to database reads.
- [ ] Inventory CSV export keeps existing URL, permission, filename, header, encoding, and semantics.
- [ ] Audit-log CSV export reuses `AUDIT_READ`.
- [ ] `/api/v1/health` returns no sensitive host, URL, password, stack trace, or exception detail.

## Schema And Index Guard

- [ ] No production DDL migration was added.
- [ ] No production schema was changed.
- [ ] Index SQL was not executed.
- [ ] `docs/115-v1.4-slow-query-index-review.md` remains documentation-only advice with rollback SQL and future approval notes.

## Release Decision

- [ ] v1.4 is acceptable for merge to `main`.
- [ ] v1.4 can be tagged only after `main` final gate and push succeed.
