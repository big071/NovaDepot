# NovaDepot v1.1 Sprint 3 Plan: Finance Ledger + Stocktake

## Goal

Sprint 3 adds the minimum finance visibility and stock accuracy controls needed after Sprint 1 and Sprint 2:

- purchase orders create payable ledgers
- sales orders create receivable ledgers
- admin can register manual payments and receipts
- warehouse users can run stocktake, enter counted quantities, confirm differences, and generate inventory adjustment transactions

This is not a full finance system and does not change the v1.0 manual inbound/outbound flow.

## Strict Scope

- Payables, receivables, payment registration, receipt registration, balance and status calculation.
- Stocktake order creation, start, count entry, difference review, final confirmation.
- Stocktake confirmation must write `inventory_transactions` with `biz_type = STOCKTAKE_ADJUST` before updating `inventory.available_qty`.
- Audit records for ledger creation, payment/receipt registration, stocktake status changes, and inventory adjustment.
- Permissions, seed data, data quality checks, and minimal E2E coverage.

## Out Of Scope

- General ledger, accounting subjects, invoices, aging, reconciliation, returns, blind stocktake, PDA/scanner flows, cycle count plans.
- CSV import, print templates, backups, tenant_id reserve work, TenantInterceptor, DeepSeek, multi-tenant runtime, billing, v1.2 or v2.0 work.
- Rework of v1.0 WMS pages or Sprint 1/Sprint 2 account and permission boundaries.

## Backend Design

- New `finance` module with controller/service/dto for payables, receivables, and registrations.
- New `stocktake` module with controller/service/dto for stocktake lifecycle.
- New tables: `payables`, `receivables`, `payments`.
- Reuse existing `stocktake_orders` and `stocktake_order_items` tables.
- Reuse `inventory_transactions` and add `STOCKTAKE_ADJUST` as the adjustment business type.
- Purchase confirm creates a payable if one does not already exist.
- Sales confirm creates a receivable if one does not already exist.
- Payment/receipt registration updates ledger paid/received amount, balance, and status.

## Status Design

- Ledger statuses: `UNPAID`, `PARTIALLY_PAID`, `PAID`, `CANCELLED`.
- Stocktake statuses: `DRAFT`, `IN_PROGRESS`, `DIFF_REVIEW`, `COMPLETED`.
- Stocktake starts by taking a current inventory snapshot into stocktake items.
- Difference confirmation fails if the current inventory has changed since the snapshot.

## Frontend Design

- Add `/erp/finance` with payable/receivable tabs, filters, balance display, and payment/receipt dialogs.
- Add `/wms/stock-take` with stocktake list, create/start/count/review/confirm actions.
- Reuse shared page/table/search/status/empty/error/confirm components.
- Keep existing WMS, ERP, CS, AI, Agent, knowledge, and audit pages stable.

## Permissions

- `FINANCE_PAYABLE_READ`
- `FINANCE_RECEIVABLE_READ`
- `FINANCE_PAYMENT_REGISTER`
- `FINANCE_RECEIPT_REGISTER`
- `STOCKTAKE_READ`
- `STOCKTAKE_CREATE`
- `STOCKTAKE_COUNT`
- `STOCKTAKE_CONFIRM`

Role defaults:

- admin: all Sprint 3 permissions
- warehouse01: stocktake read/create/count/confirm and payable read
- cs01: receivable read
- observer01: finance and stocktake read-only

## Testing And Acceptance

- `docker compose up -d mysql redis backend frontend-vue`
- `./scripts/ops/reset-commercial-baseline.ps1`
- `./scripts/ops/data-quality-check.ps1`
- `cd backend && mvn test`
- `cd frontend-vue && npm run typecheck`
- `cd frontend-vue && npm run build`
- `cd frontend-vue && npm run test:e2e`

Acceptance requires:

- ledgers are created and balances/statuses stay consistent
- unauthorized roles cannot register payments/receipts or confirm stocktake
- stocktake confirmation creates adjustment transactions and updates inventory
- audit center can find finance and stocktake operations
- v1.0 WMS, Sprint 1 ERP, and Sprint 2 WMS linkage regressions pass
