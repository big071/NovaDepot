# NovaDepot v1.2 Sprint 2: Streaming Output and Conversation Context

> Version: v1.2-S2
> Base: `develop/v1.2`
> Theme: Streaming AI replies, stop generation, conversation context window, and session archive

## 1. Goal

Sprint 2 upgrades the AI assistant from one-shot replies to streaming text output with a typewriter experience, stop generation, recent conversation context, and conversation archive management.

The implementation must preserve Sprint 1 provider routing and degradation:

- Primary provider: DeepSeek when `AI_PROVIDER=deepseek-chat` and `AI_DEEPSEEK_ENABLED=true`.
- API key variable: `AI_DEEPSEEK_API_KEY`.
- Fallback chain: DeepSeek -> RuleProvider -> MockProvider.
- No real key required for local startup or validation.

## 2. Strict Scope

Only implement:

- SSE text streaming via backend `SseEmitter` and frontend `fetch` `ReadableStream`.
- AI reply typewriter rendering.
- Stop generation.
- Streaming failure fallback to non-streaming chat.
- Recent 20 conversation rounds, implemented as the latest 40 user/assistant messages.
- Old-message truncation only; no summary compression.
- Conversation `ACTIVE / ARCHIVED`, `lastActiveAt`, and 24h inactive auto archive.
- Conversation list, create, switch, and archive.
- Streaming message status display.
- Permission, usage/audit visibility, tests, and docs.

Explicitly do not implement Function Calling, tool calls, Agent patrol, notification center, report center, RAG, vector database, knowledge graph, fine-tuning, multi-tenant runtime, billing, or v2.0 capabilities.

## 3. Design

### Backend

- Add `POST /api/v1/ai/chat/stream` returning `text/event-stream`.
- Add `POST /api/v1/ai/chat/stream/{requestId}/stop`.
- Add `POST /api/v1/ai/conversations` for explicit new sessions.
- Add `POST /api/v1/ai/conversations/{id}/archive`.
- Reuse `AI_CHAT` for chat, stream, stop, conversation create, message read, and archive.
- Add a lightweight streaming coordinator to track cancel requests by `requestId`.
- Keep RuleProvider and MockProvider available as streaming fallback by chunking their non-streaming reply.

### Database

- Add `ai_conversations.last_active_at`.
- Continue using `ai_conversations.status` with values `ACTIVE` and `ARCHIVED`.
- Add `ai_messages.status` with values `PENDING`, `STREAMING`, `COMPLETED`, `FAILED`, and `STOPPED`.
- Add indexes for active conversation archive queries and message status reads.

### Frontend

- Keep `/ai/enterprise` as the main page.
- Use `fetch` + `ReadableStream` for POST streaming with JWT auth.
- Append token content to the current assistant bubble.
- Add stop button while streaming.
- If streaming transport fails, show a clear notice and call the existing non-streaming `/ai/chat` endpoint.
- Archived sessions are visible but read-only.

## 4. Acceptance

- Streaming returns visible token-by-token output when DeepSeek is available.
- With no DeepSeek key, both streaming and non-streaming calls degrade without 500.
- Stop generation preserves partial assistant text and marks the message stopped.
- Context injection uses only the current conversation's latest 20 rounds.
- 24h inactive sessions are archived automatically.
- Existing v1.1 business flows remain unchanged.
