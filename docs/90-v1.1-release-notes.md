## v1.1 新增能力

v1.1 将 NovaDepot 从 v1.0 的智能仓库操作台升级为轻量进销存一体化系统，完成采购、入库、库存、出库、销售、应收应付和运营收口的最小闭环。

- 往来单位：统一 `partners` 模型，支持供应商、客户和两者兼具的单位。
- 采购单：基础 CRUD、确认、取消、权限、审计和种子数据。
- 销售单：基础 CRUD、确认、取消、权限、审计和种子数据。
- 采购转入库：采购单可生成入库草稿，入库单展示采购来源。
- 销售转出库：销售单可生成出库草稿，出库单展示销售去向。
- 状态联动：入库过账回写采购已收数量和状态，出库发运回写销售已发数量和状态。
- 库存不足拦截：销售转出库阶段提前校验库存，库存不足时拒绝生成草稿。
- 应付台账：采购形成轻量应付台账，支持付款登记、余额和状态。
- 应收台账：销售形成轻量应收台账，支持收款登记、余额和状态。
- 库存盘点：支持盘点单、实盘录入、差异复核、确认差异和库存调整流水。
- CSV 导入：支持产品、库存、往来单位 CSV 模板下载、部分导入和错误报告。
- 浏览器打印：支持入库单、出库单和拣货单 A4 打印。
- 数据备份：支持本地 mysqldump 压缩备份脚本、备份记录和管理员查看。
- tenant_id 预留：保留未来多租户字段和一致性检查，不启用租户过滤。

## 相比 v1.0 的变化

v1.0 重点交付 WMS、客服、AI、Agent、知识库和审计主链路。v1.1 在不破坏 v1.0 主链路的前提下，补齐了轻量 ERP 和仓库运营刚需。

| 领域 | v1.0 | v1.1 |
|---|---|---|
| WMS | 手工入库、出库、库存流水 | 保留手工流程，并支持采购/销售来源追溯 |
| ERP | 未形成采购/销售闭环 | 新增往来单位、采购单、销售单 |
| 进销存 | WMS 单链路 | 采购 -> 入库 -> 库存 -> 出库 -> 销售闭环 |
| 财务可见性 | 无轻量台账 | 新增应付、应收、付款、收款 |
| 库存校准 | 无盘点 | 新增盘点和库存调整流水 |
| 数据迁入 | 基础数据主要依赖 seed | 新增产品、库存、往来单位 CSV 导入 |
| 纸面流转 | 无打印模板 | 新增入库、出库、拣货浏览器打印 |
| 运维 | 基础备份脚本 | 增强备份脚本和备份记录 |
| 多租户 | 单租户运行 | 仅预留 `tenant_id`，不启用多租户 |

## 进销存闭环说明

v1.1 的最小业务链路如下：

1. 维护往来单位。
2. 创建并确认采购单。
3. 从采购单生成入库草稿。
4. WMS 入库单继续走 v1.0 的提交、审核、过账流程。
5. 入库过账后库存增加，采购单已收数量和状态联动。
6. 创建并确认销售单。
7. 从销售单生成出库草稿，生成前检查库存是否充足。
8. WMS 出库单继续走 v1.0 的提交、审核、发运流程。
9. 出库发运后库存减少，销售单已发数量和状态联动。
10. 采购和销售形成轻量应付/应收台账，可手工登记付款/收款。

采购/销售生成 WMS 单据只生成 `DRAFT` 草稿，不自动提交、审核、过账或发运。v1.0 手工创建入库单和出库单的能力仍然保留。

## 盘点、CSV、打印、备份说明

- 盘点：`/wms/stock-take` 支持创建盘点单、开始盘点、录入实盘、提交差异复核和确认调整。确认差异必须写入 `inventory_transactions`，业务类型为 `STOCKTAKE_ADJUST`。
- CSV：只支持 UTF-8 CSV，不支持 Excel。第一行为中文列标题，正确行可导入，错误行跳过并生成字段级错误报告。重复 SKU 或编码默认跳过，不覆盖。
- 打印：使用浏览器打印和 `@media print`，支持 A4 入库单、出库单和拣货单。打印时隐藏导航栏、按钮等无关 UI。
- 备份：`scripts/ops/backup.ps1` 和 `scripts/ops/backup.sh` 使用 mysqldump 生成 `.sql.gz` 到 `./backups/`，管理员可查看备份记录。

## tenant_id 预留说明

v1.1 只做未来多租户所需的字段预留和一致性检查：

- 不启用 TenantInterceptor。
- 不启用多租户查询过滤。
- 不修改登录流程或 token 结构。
- 当前仍按单租户方式运行。
- 数据质量检查会校验核心业务表的 `tenant_id` 预留情况。

## 已知限制

- 不支持 Excel `.xlsx` 导入。
- 不支持导入回滚或覆盖导入。
- 不支持批量打印、标签打印机和自定义打印模板设计器。
- 不支持自动恢复、云备份、异地备份和增量备份。
- 应收应付是轻量台账，不是总账、明细账或完整财务系统。
- 付款/收款为单台账手工登记，不做复杂核销、账龄分析和自动对账。
- 不支持采购退货、销售退货、发票、合同、报价和询比价。
- 多租户、计费和正式付费 AI Provider 不属于 v1.1。
- 当前环境曾出现 Docker Hub token/metadata 拉取超时，若重建前端镜像失败，应先恢复 Docker Hub 网络后重试。

## 后续 v1.2 路线

v1.2 建议围绕智能化增强规划，不在 v1.1 中提前实现：

- DeepSeek 或其他付费 AI Provider 的正式接入。
- 更强的 AI 分析、知识引用和运营建议能力。
- 报表和通知能力增强。
- 更完整的数据洞察和异常发现能力。

多租户正式启用、计费、商业化平台运营仍建议归入 v2.0。
