# NovaDepot 前端设计系统与交互规范

## 1. 整体视觉风格建议
- 定位：企业级 SaaS 后台，强调“高密度信息可读 + 高效率操作”。
- 风格关键词：克制、硬朗、专业、清晰、可追踪。
- 视觉策略：中性基底 + 功能色突出状态；弱装饰、强结构。
- 布局原则：固定导航骨架（顶部 + 左侧），主内容区支持高密度表格与多面板协作。

## 2. 色彩系统建议
## 2.1 语义色
| 语义 | Light | Dark | 用途 |
|---|---|---|---|
| `bg` | `#F6F8FB` | `#0F131A` | 页面背景 |
| `surface` | `#FFFFFF` | `#171C25` | 卡片/弹层 |
| `text-primary` | `#111827` | `#E6EAF2` | 主文本 |
| `text-secondary` | `#4B5563` | `#9AA4B5` | 次文本 |
| `primary` | `#1D4ED8` | `#3B82F6` | 主操作 |
| `success` | `#16A34A` | `#22C55E` | 成功 |
| `warning` | `#D97706` | `#F59E0B` | 警告 |
| `danger` | `#DC2626` | `#EF4444` | 错误 |
| `info` | `#0891B2` | `#06B6D4` | 信息 |

## 2.2 状态色映射（单据）
- 草稿 `gray`
- 审核中 `blue`
- 执行中 `cyan`
- 已完成 `green`
- 已作废 `slate`
- 异常 `red`

## 3. 字体层级建议
- 中文优先字体栈：`"Noto Sans SC","PingFang SC","Microsoft YaHei",sans-serif`
- 数字与表格：`"IBM Plex Sans","Noto Sans SC",sans-serif`

| 层级 | 建议 |
|---|---|
| 页面标题 | 24/32, 600 |
| 区块标题 | 18/28, 600 |
| 卡片标题 | 16/24, 600 |
| 正文 | 14/22, 400 |
| 辅助文案 | 12/18, 400 |
| 表格数字 | 13/20, 500（等宽对齐） |

## 4. 间距系统建议
- 基础单位：`4px`。
- 间距尺度：`4/8/12/16/20/24/32/40/48`。
- 页面网格：内容区左右 `24px`（移动端 `16px`）。
- 表单纵向间距：`16px`，复杂分组 `24px`。

## 5. 圆角、阴影、边框规范
| 元素 | 规范 |
|---|---|
| 圆角 | 输入框/按钮 `8px`，卡片 `12px`，弹窗 `14px` |
| 边框 | `1px`，低对比中性边框 |
| 阴影 | 卡片轻阴影，弹窗中阴影，避免大面积浮夸阴影 |
| 分割线 | 高频使用，提升高密度信息分区可读性 |

## 6. 核心组件规范
| 组件 | 规范 |
|---|---|
| 按钮 | 主按钮实色、次按钮描边、危险按钮红色；最小点击高 `36px` |
| 输入框 | 默认/聚焦/错误/禁用四态明确；支持前后缀与清空 |
| 表格 | 固定表头、列宽可调、密度切换、行操作固定右侧 |
| 弹窗 | 适合确认与轻编辑，宽度 480/640/800 三档 |
| 抽屉 | 适合中复杂编辑与侧边详情；支持右侧 40%-60% 宽度 |
| 标签 | 语义化状态 tag，颜色与状态机一致 |
| 卡片 | 信息聚合 + 快捷动作；标题区与内容区分离 |
| 通知 | 右上角 toast，业务通知进入通知中心可追溯 |

## 7. 列表页规范
- 结构：筛选区 -> 工具栏 -> 数据表格 -> 分页。
- 筛选区默认一行，展开显示高级筛选。
- 工具栏左侧批量操作，右侧导入导出、列设置、密度切换。
- 表格支持：排序、筛选、列冻结、行内快捷操作。
- 高密度场景优先可读性，减少装饰动效。

## 8. 详情页规范
- 结构：状态条 + 基础信息卡 + 明细表 + 操作日志 + 审批轨迹。
- 关键状态与下一步动作固定在顶部。
- 明细变更用高亮对比展示。
- 操作按钮按状态机动态出现，禁止非法动作入口。

## 9. 表单页规范
- 新建页：分段表单，支持草稿保存。
- 编辑页：展示“最近修改时间/人”。
- 校验策略：实时校验 + 提交校验双层。
- 高风险提交（出库扣减、入库入账）必须二次确认。

## 10. 仪表盘规范
- 布局：KPI 卡片（第一屏）+ 趋势图（第二屏）+ 异常列表（第三屏）。
- 卡片需支持点击钻取到对应业务页。
- 数字使用千分位，异常值颜色高亮。
- 保持“看板不是报表页”，避免放太多筛选器。

## 11. 图表规范
- 图表库：Recharts 为主，复杂图用 ECharts。
- 色彩：与语义色一致，避免同屏超过 6 种主色。
- 图例：默认可点击筛选，支持 tooltip 明细。
- Y 轴必须标单位，时间轴统一格式。
- 图表容器需有空态、加载态、错误态。

## 12. 动效规范（Framer Motion）
## 12.1 强动效页面（适合）
- `/dashboard`：卡片入场、数字滚动、图表渐进绘制。
- `/cs/workspace`：新消息入场、会话切换过渡、建议回复插入反馈。
- `/ai/enterprise` `/ai/warehouse`：流式回复、引用来源展开动画。

## 12.2 克制动效页面（必须）
- `/wms/inventory` `/wms/inventory/ledger`：仅保留 hover 与状态变更反馈。
- `/wms/outbound/picking`：避免干扰，优先即时反馈和性能。
- 所有单据列表页：不做复杂转场，确保筛选与翻页响应。

## 12.3 动效原则
- 动效只服务业务反馈：状态变化、操作结果、上下文切换。
- 时长建议：`120ms/180ms/240ms`。
- 避免连续大位移和过度弹性动画。

## 13. 加载态、空状态、错误状态规范
| 状态 | 规范 |
|---|---|
| 加载态 | 列表用骨架屏，按钮用 loading，图表用占位框 |
| 空状态 | 给出原因 + 下一步操作按钮（创建/导入/调整筛选） |
| 错误态 | 错误码 + 可读提示 + 重试按钮 + `traceId` |

## 14. 权限禁用与只读态规范
- 无权限页面：展示 403 状态页与申请权限入口。
- 字段级无权限：显示脱敏或占位符，不直接隐藏关键业务上下文。
- 只读态页面：操作按钮置灰并显示原因 tooltip。
- 非法状态操作：按钮不可点并显示当前状态限制说明。

## 15. 移动端适配建议
- 断点建议：`<768` 移动、`768-1279` 平板、`>=1280` 桌面。
- 移动优先页面：
  - 拣货复核
  - 入库任务
  - 盘点录入
  - 通知与待办
  - 客服会话处理
- 移动端减少列，采用卡片化列表与底部主操作按钮。

## 16. AI 助手聊天页设计规范
- 三段式布局：左侧历史会话、中间聊天区、右侧引用数据面板。
- 消息类型：用户、助手、系统提示、数据引用卡。
- 支持“回答依据”展开，显示来源报表/库存数据链接。
- 输入区支持快捷问题模板、回车发送、Shift+Enter 换行。
- 对 mock/rule/paid provider 显示 provider 标识，便于测试验证。

## 17. 智能客服工作台设计规范
- 三栏布局：
  - 左：会话队列（状态/优先级/SLA）
  - 中：消息窗口 + 建议回复
  - 右：客户信息、订单、库存、工单
- 必须支持快捷动作：转人工、建工单、插入模板、标记完成。
- SLA 超时视觉提醒固定可见。
- 高并发场景优先稳定性，减少非必要动画。

## A. 设计关键词
`专业` `高密度可读` `状态驱动` `反馈即时` `克制动效` `可追溯`

## B. 首页仪表盘风格建议
- 深浅模式都采用“低饱和背景 + 高对比卡片”。
- KPI 卡片突出异常指标，趋势图支持一键钻取到业务列表。
- 动效重点放在首屏数据入场和异常提醒，不做复杂场景切换。

## C. 智能助手页风格建议
- 强调“对话 + 证据链”，回答旁必须可查看数据来源。
- 使用轻量流式动效体现“正在分析”，完成后稳定落版。
- 支持一键复制、追问、跳转相关业务页面。

## D. 客服工作台风格建议
- 信息密度高但分区清晰，优先保障坐席连续操作效率。
- 新消息与 SLA 风险采用明确但克制的动态提示。
- 右侧业务上下文（订单/库存）需常驻，减少页面跳转成本。

## 18. Docker 运行与环境变量配置建议（前端）

## 18.1 运行方式
- 本地桌面：`frontend` 通过 Docker Compose 启动，访问 `http://localhost:3000`。
- 联调：前端通过环境变量访问 `backend` API。

## 18.2 环境变量建议
| 变量 | 示例 | 用途 |
|---|---|---|
| `NEXT_PUBLIC_API_BASE_URL` | `http://localhost:8080/api/v1` | API 基础地址 |
| `NEXT_PUBLIC_APP_NAME` | `NovaDepot` | 应用名 |
| `NEXT_PUBLIC_ENABLE_MOCK_AI` | `true` | 前端 AI 调试开关 |

## 18.3 分环境建议
- `.env.local`：本机开发
- `.env.docker`：Docker 容器联调
- `.env.production`：正式环境

## 18.4 Docker Compose 联调体验建议
- `frontend` 与 `backend` 同网络，保持 API 路径一致。
- 前端错误页展示 `traceId`，便于后端日志定位。
- 登录失效统一跳转 `/login`，并保留原路径回跳。
