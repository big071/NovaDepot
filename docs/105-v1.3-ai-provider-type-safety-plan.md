# v1.3 Sprint Q3 AiProvider Type Safety Plan

> Status: ACT PLAN
> Sprint: v1.3 Q3
> Scope: internal AI provider DTO migration only, with public behavior preserved.

## Summary

Sprint Q3 replaces AI provider result maps with typed DTOs. It is not an AI feature sprint.

Q3 must preserve:

- `/api/v1/ai/chat` response keys and value semantics.
- `/api/v1/ai/chat/stream` SSE event names and payload keys.
- DeepSeek success and explicit no-fallback failure behavior.
- `AI_PROVIDER=rule` direct RuleProvider behavior.
- Function Calling read-only tools, tool cards, no-result warnings, and final answer structure.
- `ai_usage_logs` semantics.
- Existing routes, permissions, database schema, environment variable names, and frontend behavior.

## Current Map Usage

`AiProvider.chat(...)` currently returns `Map<String,Object>` and is implemented by `DeepSeekChatAiProvider`, `DeepSeekReasonerAiProvider`, `RuleAiProvider`, `MockAiProvider`, and `PaidAiProvider`.

`AiChatService` and `AiStreamService` read provider result keys directly, including `reply`, `confidence`, `tokens`, `model`, `usage`, `toolCalls`, `metrics`, and `suggestions`.

`AiFunctionCallingOrchestrator` reads `toolCalls` from the provider result map and converts them into internal tool calls.

## Target DTOs

Q3 introduces the smallest useful provider DTO set:

- `AiProviderResponse`: reply, scene, provider, model, confidence, tokens, success, errorCode, errorMessage, usage, toolCalls, metrics, suggestions, metadata.
- `AiProviderUsage`: promptTokens, completionTokens, totalTokens, latencyMs, costEstimate.
- `AiProviderToolCall`: id, name, argumentsJson, resultSummary, success, errorCode.
- `AiProviderError`: code, message, statusCode, retryable.
- `AiProviderResponseMapper`: centralized conversion to the existing external map shape and Function Calling input shape.

Existing `AiProviderCallException` remains the DeepSeek failure mechanism.

## Implementation Order

1. Add provider DTOs and mapper.
2. Add characterization tests for provider mapping and external response shape.
3. Change `AiProvider.chat(...)` to return `AiProviderResponse`.
4. Migrate Mock, Paid, Rule, DeepSeek Chat, and DeepSeek Reasoner providers.
5. Update `AiChatService`, `AiStreamService`, and `AiFunctionCallingOrchestrator` to consume typed responses.
6. Remove provider result map reads from chat and stream services.
7. Keep maps only for request body, metadata, external compatibility, tool result maps, and business data lists.

## Test Plan

Required backend coverage:

- DeepSeek provider response mapping.
- DeepSeek failure mapping through `AiProviderCallException`.
- Token usage mapping.
- Tool call mapping.
- RuleProvider response mapping.
- MockProvider response mapping.
- PaidProvider placeholder response mapping.
- Chat response external shape unchanged.
- Stream event external shape unchanged smoke.
- Function Calling tool card and final answer no-regression.

## Acceptance

Q3 is complete when:

- `AiProvider.chat(...)` no longer returns `Map<String,Object>`.
- All provider implementations return `AiProviderResponse`.
- Chat and stream services consume typed provider responses internally.
- External chat response and SSE event shapes remain unchanged.
- Function Calling tool cards and final answer structure remain unchanged.
- Full validation passes or any environment-only issue is documented.
- No API, schema, permission, env var, frontend, or released business behavior change is introduced.
