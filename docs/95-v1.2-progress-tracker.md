## Sprint 1 Acceptance Notes

- DeepSeek is explicit opt-in via `AI_DEEPSEEK_ENABLED=true` plus `AI_DEEPSEEK_API_KEY`.
- Without a real API key, validation is limited to the RuleProvider/MockProvider degradation chain and configuration safety.
- API keys are read from environment configuration and only returned to the frontend as masked status.
- `ai_usage_logs` records DeepSeek success and DeepSeek degradation events with provider, success flag, latency, and error reason.

## Sprint 2 Completed Items

- Added Sprint 2 implementation plan: `docs/96-v1.2-sprint2-streaming-context-plan.md`.
- Added database migration `109-schema-v1.2-sprint2-streaming-context.sql` for `ai_conversations.last_active_at`, `ai_messages.status`, status normalization, and supporting indexes.
- Added backend SSE endpoint `POST /api/v1/ai/chat/stream` and stop endpoint `POST /api/v1/ai/chat/stream/{requestId}/stop`.
- Added conversation create/archive endpoints and 24h inactive auto archive scheduler.
- Added request-scoped stream cancellation registry.
- Added recent 20-round context window using latest 40 current-conversation messages; no summary compression and no cross-session memory.
- Preserved RuleProvider/MockProvider degradation for no-key operation and streaming fallback.
- Added frontend `fetch` `ReadableStream` parser, typewriter assistant bubble, stop button, stream status, archived-session read-only state, new conversation, switch conversation, and archive controls.
- Extended smoke/E2E/data-quality checks for Sprint 2 AI streaming/session behavior.
- Unified docs/config references on `AI_PROVIDER`, `AI_DEEPSEEK_ENABLED`, and `AI_DEEPSEEK_API_KEY`.

- No changes were made to v1.1 business workflows or the Sprint 1 API key masking strategy.

## Sprint 3 Completed Items

- Added Sprint 3 implementation plan: `docs/97-v1.2-sprint3-function-calling-plan.md`.
