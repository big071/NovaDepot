# v1.3 Q10-Q12 Final Quality Cleanup Plan

## 1. Goal

Q10-Q12 closes the remaining v1.3 quality cleanup scope without adding business features, changing API contracts, changing database schema, changing permissions, or changing AI provider behavior.

Execution order:

1. Q10 CustomerService / Knowledge cleanup.
2. Q11 Frontend non-AI component cleanup.
3. Q12 Docker / CI / static analysis hardening.

Each stage must stop on test failure, scope drift, or behavior-change risk.

## 2. Q10 Scope and Result

Q10 may change only CustomerService / Knowledge backend structure, focused backend tests, and this document.

Implemented approach:

- Keep `CustomerServiceController` and `KnowledgeController` route, request, response, and permission boundaries unchanged.
- Convert `CustomerServiceService` into a thin facade over responsibility services:
  - `CustomerConversationService`
  - `CustomerTicketService`
  - `CustomerAiSuggestionService`
  - `CustomerFaqService`
- Convert `KnowledgeService` into a thin facade over responsibility services:
  - `KnowledgeFaqService`
  - `KnowledgeSopService`
  - `KnowledgeRuleService`
  - `CustomerKnowledgeDraftService`
  - `KnowledgeMatchService`
- Preserve existing map response keys at controller-facing boundaries.
- Keep original business logic inside internal core services during this stage to minimize regression risk.

Non-goals:

- No ticket status-machine changes.
- No customer-service flow changes.
- No FAQ/SOP approval-rule changes.
- No knowledge permission changes.
- No schema changes.

## 3. Q11 Scope and Result

Q11 may change only non-AI frontend pages/components/composables/tests and this document.

Planned implementation:

- Split `AgentCenterPage.vue` into focused non-AI components for task selection, run result, and run history.
- Split `CustomerServicePage.vue` into focused non-AI components for session list, AI suggestion display, and ticket list.
- Keep route definitions, permission guards, API calls, request/response contracts, and visual design behavior unchanged.
- Keep `ReportsPage.vue` intact unless low-risk type cleanup is needed.

## 4. Q12 Scope and Result

Q12 may change only Docker/CI/static-analysis configuration, package scripts, docs, and this document.

Planned implementation:

- Improve `.dockerignore` coverage for local caches, build output, test output, env files, and logs.
- Keep Docker Compose service names, ports, environment variable semantics, and startup behavior stable.
- Keep frontend Dockerfile pinned.
- Move backend runtime image to a versioned JRE runtime image if validation remains green.
- Add only low-risk frontend check scripts.
- Record Checkstyle / SpotBugs as backlog unless it can be introduced without forcing unrelated business-code churn.

Implemented result:

- Expanded root, backend, and frontend Docker ignore files for env files, logs, caches, build output, and test artifacts.
- Kept Docker Compose service topology and environment semantics unchanged.
- Switched backend runtime image from Maven runtime to a JRE runtime image while preserving the builder stage, profile, port, and entrypoint.
- Added a frontend `check` script that composes existing typecheck, build, and unit-test commands.
- Left Checkstyle / SpotBugs as backlog to avoid broad unrelated code churn.
