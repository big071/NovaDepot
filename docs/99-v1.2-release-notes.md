# NovaDepot v1.2 Release Notes

> Version: v1.2
> Branch: `develop/v1.2`
> Release theme: DeepSeek intelligence core, streaming context, Function Calling tools, Agent patrol, notifications, and reports.

## New Capabilities

- DeepSeek-compatible AI provider integration with explicit opt-in via `AI_DEEPSEEK_ENABLED` and `AI_DEEPSEEK_API_KEY`.
- RuleProvider and MockProvider degradation remain available when no real key is configured.
- AI usage logs and API key masking preserve Sprint 1 security boundaries.
- Streaming AI response, typewriter UI, stop generation, recent 20-round context window, conversation switching, and session archive.
- Read-only Function Calling tools for inventory, inbound, outbound, purchase, sale, tickets, products, partners, inventory stats, and daily report.
- Tool-call visualization, evidence sources, no-result/no-permission messaging, call limit, tool audit logs, and data-quality checks.
- Scheduled Agent patrols for low stock, overdue documents, and overdue tickets.
- In-app notification center with unread badge, list, read/read-all, and jump links.
- Fixed report center with inventory turnover, inbound/outbound summary, purchase/sales summary, ticket efficiency, and CSV export.
- Audit-log cleanup with configurable retention days and cleanup audit records.

## Compatibility

- v1.1 WMS, ERP, CS, RBAC, audit, import, backup, and data-quality flows remain unchanged.
- v1.2 keeps the single-tenant runtime architecture while preserving `tenant_id` fields for future work.
- Function Calling and Agent patrols are read-only; no AI automatic approval, stock modification, document creation, or customer-message sending is included.

## Known Limits

- No external notification channels: email, SMS, enterprise chat, and mobile push are out of scope.
- No RAG, vector database, knowledge graph, model training/fine-tuning, multi-tenant runtime, billing, custom report designer, or BI dashboard.
- Reports are real-time fixed queries and do not use report cache tables.
- Docker Hub token or metadata timeout remains an environment-network issue; retry after network recovery.
