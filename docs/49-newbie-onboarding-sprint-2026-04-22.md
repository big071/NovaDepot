# NovaDepot 新手上手模式 Sprint（2026-04-22）

## 1. 目标
将系统从“会用的人能用”提升为“第一次接触仓储系统的小白也能快速理解并完成核心操作”。

## 2. 边界
1. 仅做易用性与业务语义增强，不扩展复杂业务模块。
2. 不重做整体架构，不进入多租户与计费开发。
3. 保持现有接口契约和 Docker 本地运行方式。

## 3. 当前新手痛点
1. 首页缺少“我要做什么”的任务入口。
2. 入库/出库状态动作多，缺少状态到下一步的解释。
3. 多页面以 ID 为主，业务名不突出。
4. 商品、仓库、库位关系解释不足。
5. 客服页面会话/工单/FAQ 关系未显式说明。
6. AI 页面缺少“可直接点击的推荐问题”。
7. 空页面缺少下一步建议，用户容易停滞。
8. 入库/出库创建表单一次性暴露字段较多。
9. 工单创建入口缺少“何时创建”的语义说明。
10. 详情查看虽然多为弹窗，但信息结构与提示文案不统一。

## 4. 本轮执行范围
1. 首页新手入口：
   1. 仪表盘增加快捷任务区。
   2. 提供 5 个入口并附一句说明：
      - 我要入库
      - 我要出库
      - 我要看低库存
      - 我要处理客服工单
      - 我要看今日经营情况
2. 关键页面新手引导：
   1. 商品页：解释商品主数据含义与先建商品原因。
   2. 仓库页：解释仓库与库位关系。
   3. 库位页：解释库位用途差异。
   4. 入库页：解释标准操作步骤。
   5. 出库页：解释标准操作步骤。
   6. 客服页：解释会话、工单、FAQ 关系。
   7. AI 页：提供推荐问题按钮和示例提问。
3. 空态和下一步引导：
   1. 商品为空时引导创建商品。
   2. 仓库为空时引导创建仓库。
   3. 库位为空时引导创建库位。
   4. 工单为空时引导从会话创建工单。
   5. AI 无会话时给推荐提问。
4. 表单减负（最小可用）：
   1. 入库/出库创建表单改为分组显示（基础信息 / 明细信息）。
   2. 工单创建语义加强（用途提示 + 默认内容建议）。
   3. 关键动作文案明确“会发生什么”。

## 5. 验收标准
1. 仪表盘展示 5 个快捷任务入口并可跳转。
2. 关键页面均有新手说明区，且文案与业务术语一致。
3. 空态均提供下一步建议，不出现“无数据后无动作指引”。
4. AI 页面可通过推荐问题快速触发有效提问。
5. 入库/出库/工单创建交互复杂度下降，字段暴露更可控。
6. 保存/提交/撤回/作废/过账/发运语义清晰，新手可理解。
7. 改动不影响 Docker 本地部署与主链路运行。

## 6. 验证步骤（执行口径）
1. 启动：`docker compose up -d mysql redis backend frontend-vue`
2. 重置样本：`./scripts/ops/reset-commercial-baseline.ps1`
3. 登录后逐页验证：
   1. 仪表盘快捷任务区入口与跳转。
   2. 商品/仓库/库位新手说明与空态建议。
   3. 入库/出库步骤说明、分组表单、状态动作提示。
   4. 客服页会话/工单/FAQ 关系说明与空态引导。
   5. AI 页推荐问题按钮与无会话引导。
4. 回归检查：
   1. 入库链路：创建 -> 提交 -> 审核 -> 过账。
   2. 出库链路：创建 -> 提交 -> 审核 -> 发运。
   3. 客服链路：会话发消息 -> 创建工单 -> 更新状态。
   4. AI 链路：推荐提问 -> 返回建议 -> 会话可回看。

## 7. 风险与控制
1. 风险：引导文案与真实状态规则不一致。
2. 控制：文案与后端状态机保持一致，不新增虚假动作。
3. 风险：页面提示过多导致干扰。
4. 控制：仅在关键模块与空态展示，保持简短和可执行。
