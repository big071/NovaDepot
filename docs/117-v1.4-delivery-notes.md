## Database Impact

No production schema changes were introduced. v1.4 adds only idempotent seed DML for the minimal `ROLE_MANAGE` permission in the existing RBAC seed file.

The slow-query index document contains SQL advice only. It does not add migrations and does not execute DDL.

## Permission Impact

`ROLE_MANAGE` is the new minimal management permission for role write operations. It is granted only through the existing management role seed path. Warehouse, customer-service, and observer accounts must not receive role-management permission.

Built-in roles are preserved and protected from v1.4 editing.

## Security Impact

- No `.env`, real API key, JWT secret, database password, private key, or access token is committed.
- The health endpoint reports only UP/DOWN status for the service, MySQL, and Redis.
- Role write operations are audited.
- Audit-log export reuses `AUDIT_READ`.
- Cache logic does not store permissions, login state, JWT, API keys, passwords, or inventory quantities.

## Redis Cache Consistency

Reference data uses cache-aside reads with short TTL. Products, warehouses, locations, and partners evict their module cache after create, update, disable, or import paths. Redis failures fall back to database reads and log warnings without changing business responses.

## CSV Export Compatibility

Inventory export keeps the existing `/api/v1/inventory/export` path, permission, filename, CSV header, encoding, and download semantics while using streaming output.

Audit-log export is additive at `/api/v1/audit-logs/export` and reuses existing audit filter parameters and `AUDIT_READ`.

## Docker And Healthcheck

The backend Docker image includes the lightweight curl dependency required by the compose healthcheck. The compose stack remains `mysql`, `redis`, `backend`, and `frontend-vue`.

## Rollback Advice

1. Disable the frontend role-management route if the UI must be hidden quickly.
2. Revert the v1.4 commit to remove RBAC write endpoints, reference caching, streaming export changes, healthcheck wiring, and E2E additions together.
3. The seed DML is idempotent; no production schema rollback is required.
4. Index SQL in `docs/115-v1.4-slow-query-index-review.md` was not executed, so no index rollback is needed for v1.4.
