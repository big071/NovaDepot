# NovaDepot v1.0 演示说明

---

## 演示准备

1. 确保 Docker Desktop 已启动
2. 执行 `docker compose up -d` 启动全部服务
3. 等待约 30 秒服务就绪
4. 打开浏览器访问 http://localhost:3100

---

## 5 分钟快速演示

### 步骤 1：登录展示 (30秒)
- 使用 `admin / admin123` 登录
- 展示管理员首页：待审核单据、待异常处理
- 退出登录

### 步骤 2：仓储运营 (90秒)
- 使用 `warehouse01 / pass123` 登录
- **库存总览**：展示库存列表和低库存预警（螺丝 M8 = 15 < 50）
- **入库操作**：点击创建入库单 → 选择产品 → 输入数量 → 提交 → 审核 → 执行
- **出库操作**：点击创建出库单 → 选择产品 → 输入数量 → 提交 → 审核 → 发运

### 步骤 3：客服与工单 (90秒)
- 使用 `cs01 / pass123` 登录
- **客服会话**：查看会话列表，打开一个会话，展示消息时间线
- **AI 建议回复**：在输入框输入客户问题，展示 AI 建议
- **创建工单**：从会话创建工单 → 指定状态和优先级
- **处理工单**：更改工单状态、添加备注、展示处理历史时间线

### 步骤 4：AI 助手 (30秒)
- 使用 `admin / admin123` 登录
- **AI 助手对话**：发送 "如何入库?" → 展示 AI 回复 → 展示 FAQ 引用来源
- **Agent 任务**：执行 "低库存分析" → 展示分析结果和建议

### 步骤 5：审计与收尾 (60秒)
- **审计中心**：展示操作审计日志 → 按模块筛选 → 按操作人筛选
- **知识库**：展示 FAQ 列表 / SOP 列表 → 规则配置页面

## 关键演示台词

### 核心信息
> "NovaDepot v1.0 是一个智能仓储管理 + 客服 + AI 助手一体化平台，面向 3-15 人小团队，Docker 一键启动，支持 admin/warehouse/cs/observer 四种角色协同工作。"

### 入库流程
> "仓储运营创建入库单后提交审核，管理员审核通过后执行入库，库存自动更新。"

### 出库流程
> "出库时系统会检查库存是否充足。如果库存不足，发运会失败并提示明确错误信息。"

### AI 与 Agent
> "AI 助手基于企业知识库的 FAQ/SOP/规则给出回答，Agent 可以自动分析低库存、提供补货建议和异常巡检。"

### 权限
> "系统有完整的 RBAC 权限控制，非管理员无法访问审计中心，也无法修改规则配置。"

## 常见演示 Q&A

**Q: 数据是真实的吗？**
A: 种子数据是演示用的商业基线数据，包含上海主仓和昆山分仓，10 种产品，4 个用户账号。

**Q: AI 接的是哪个模型？**
A: 当前使用 Mock + Rule Provider，基于本地 FAQ/SOP 知识库匹配。已预留 Provider 抽象层，未来可切换到付费 API。

**Q: 如何重置数据？**
A: 运行 `./scripts/ops/reset-commercial-baseline.ps1` 即可恢复到干净基线。

**Q: 支持多租户吗？**
A: v1.0 是单租户架构，多租户规划在 v2.0。

## 演示注意事项

1. **提前启动服务**：Docker 首次启动可能需要拉取镜像，提前 5 分钟启动
2. **避免生产数据**：演示使用种子数据，不要导入真实业务数据
3. **网络稳定**：确保 Docker 网络正常，端口 3100 和 18080 未被占用
4. **浏览器**：推荐 Chrome/Edge 最新版
5. **窗口大小**：建议 1920×1080 或以上，确保 UI 布局正常
