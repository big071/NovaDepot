# NovaDepot v1.4 Ops & Admin Readiness Plan

> Version: v1.4
> Theme: Ops & Admin Readiness before v2.0 planning.

## Scope

v1.4 closes low-risk administration and operations gaps after the v1.3 quality release. It prepares NovaDepot for v2.0 planning without entering v2.0.

Included:

- Role and permission management on the existing RBAC tables.
- Redis cache for stable reference data only.
- Slow-query and index review as documentation-only advice.
- Streaming CSV export for inventory and audit logs.
- Lightweight health check and Docker backend healthcheck.
- E2E coverage for role management, permission control, CSV export, and login rate limiting.
- Small residual cleanup with no broad formatting.

## Non-Goals

- No new ERP, WMS, or customer-service business modules.
- No production database schema changes or migrations.
- No API path, parameter, response-shape, or HTTP semantic changes for existing endpoints.
- No change to existing permission semantics.
- No v2.0 multi-tenant runtime, TenantInterceptor, billing, RAG, vector database, knowledge graph, multimodal AI, or mobile app.
- No large dependency replacement, frontend migration, ORM replacement, auth-system replacement, release tag, or `npm audit fix`.

## Module Gates

1. Role management must preserve built-in roles and demo account permissions.
2. Redis cache must never store inventory quantities, permissions, login state, JWT, API keys, passwords, or secrets.
3. Slow-query review must stay document-only; DDL must be approved in a later release.
4. CSV streaming must preserve existing inventory export URL, filename, headers, encoding, and permissions.
5. Health checks must not expose hostnames, credentials, stack traces, or detailed exception text.
6. E2E tests must not create login users or weaken real permission checks.
7. Cleanup must be limited to behavior-neutral logging/import/comment cleanup.
