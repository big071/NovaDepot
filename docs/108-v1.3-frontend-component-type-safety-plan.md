# v1.3 Sprint Q6 Frontend Component and Type Safety Cleanup

## 1. Scope

Q6 is a frontend quality cleanup sprint. It keeps business behavior, API routes, response shapes, permissions, backend business logic, database schema, and AI provider behavior unchanged.

Allowed implementation scope:

- Split the `/ai/enterprise` page display layer into typed Vue components.
- Move pure AI presentation helpers into a frontend utility module.
- Replace the two known explicit `any` usages with safer types.
- Add a minimal Vitest + Vue Test Utils unit-test foundation.
- Keep Playwright E2E as the primary behavior regression gate.

## 2. Current Baseline

- Current branch: `develop/v1.3`.
- Main frontend risk: `frontend-vue/src/pages/ai/AiAssistantPage.vue`, previously a large container/display mixed component.
- Explicit `any` baseline before Q6: 2 usages.
- Existing E2E baseline after Q5: 24 Playwright tests.
- `tsconfig.json` already has `strict: true`; Q6 does not change global compiler strictness.
- Vitest was not configured before Q6.

## 3. Component Split

The AI page remains the stateful container for requests, streaming, conversations, messages, and routing. The extracted components are presentation-only and use typed props/emits.

- `AiConversationSidebar`: conversation list, new/refresh actions, empty-state recommended questions, conversation selection.
- `AiProviderStatusBar`: title area, active conversation status, scene selector, archive action, DeepSeek configuration warning, knowledge references, recommended questions, task result panel.
- `AiMessageList`: message scroll area, loading state, empty-state recommended questions.
- `AiMessageCard`: user and assistant message rendering, structured answer sections, validation warnings, tool-limit state, message status.
- `AiToolEvidencePanel`: tool evidence collapse panel, tool status labels, source labels, summaries.
- `AiInputBar`: prompt input, send action, stop-generation action, error display.

## 4. Type Safety Cleanup

- `DashboardPage.vue`: replace `Record<string, any>` with `Record<string, unknown>` and safe numeric/object access helpers.
- `CustomerServicePage.vue`: type the ticket timeline table rows with `TicketTimelineItem`.
- `services/ai.ts`: keep SSE wire shape unchanged, but add minimal typed payloads for `meta`, `status`, and `done` events.
- `types/aiView.ts`: centralize AI page view types shared by the container and extracted components.

## 5. Vitest Foundation

Q6 adds the minimal unit-test foundation:

- `vitest`
- `@vue/test-utils`
- `jsdom`
- `vitest.config.ts`
- `npm run test:unit`

Initial tests cover:

- `StatusBadge` status-to-tag mapping.
- `EmptyState` description and extra slot.
- `AiToolEvidencePanel` success/failure/permission/empty states.
- `aiPresentation` parsing, risk highlighting, failure guidance, tool/source labels.

## 6. Non-Goals

Q6 does not:

- Rewrite the frontend architecture.
- Change UI design style or business interaction flow.
- Change routes, permissions, API request/response shapes, backend logic, database schema, or AI provider behavior.
- Split WMS, ERP, CS, Dashboard, or other large pages beyond the two explicit `any` fixes.
- Add new business features.
- Introduce large frontend dependencies.

## 7. Regression Plan

Frontend gates:

```powershell
cd frontend-vue; npm run typecheck
cd frontend-vue; npm run build
cd frontend-vue; npm run test:unit
cd frontend-vue; npm run test:e2e
```

Full v1.3 regression gate:

```powershell
cd backend; mvn test
docker compose up -d mysql redis backend frontend-vue
./scripts/ops/reset-commercial-baseline.ps1
./scripts/ops/data-quality-check.ps1
```

## 8. Acceptance Criteria

- `AiAssistantPage.vue` is significantly smaller and acts as the AI page container.
- AI display UI is split into typed components with no new state-management layer.
- Explicit `any` count in `frontend-vue/src` is reduced to zero.
- Vitest unit-test foundation exists and runs with the initial test set.
- `/ai/enterprise` streaming output, stop generation, tool evidence, failure messages, provider/fallback status, and recommended-question behavior stay unchanged.
- No backend, schema, permission, API contract, or AI provider behavior changes are introduced.

## 9. Rollback Strategy

- Revert AI component wiring first if `/ai/enterprise` behavior regresses.
- Keep pure utility extraction and Vitest foundation only if they remain independently passing.
- If Vitest dependency installation causes environment issues, remove the unit-test wiring and record the gap for a later frontend testing sprint.
