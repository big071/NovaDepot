# NovaDepot v1.1 Sprint 2 Plan: Procurement/Sales WMS Link

## Summary

Sprint 2 connects the Sprint 1 ERP foundation with the v1.0 WMS flow. The goal is to generate inbound drafts from confirmed purchase orders and outbound drafts from confirmed sales orders, keep manual WMS creation available, show source/target traceability, sync received/shipped quantities after WMS completion, and block sales-to-outbound conversion when stock is insufficient.

## Current Gap

- Purchase and sales orders support basic CRUD and confirmation, but they cannot generate WMS drafts.
- Inbound and outbound orders do not show ERP source information.
- Purchase `received_qty` and sales `shipped_qty` are not updated by WMS completion.
- Stock shortage is checked during outbound shipment, but Sprint 2 also requires shortage blocking before sales conversion.
- Conversion, source binding, and status sync audit events are missing.

## Strict Scope

- Purchase order -> inbound draft only.
- Sales order -> outbound draft only.
- Inbound shows purchase source; outbound shows sales target.
- Purchase status syncs from inbound posted quantity.
- Sales status syncs from outbound shipped quantity.
- Sales conversion checks available stock first and returns a business message on shortage.
- Permissions, audit, seed data, minimal E2E, and v1.0 WMS regression.

## Out of Scope

- No receivables/payables, stocktake, CSV import, print templates, backup scripts, tenant reservation, DeepSeek, multi-tenant, billing, returns, invoices, contracts, quotes, or complex BPM.
- No complex split-order UI or complex partial receipt/shipment UI.
- No changes to Sprint 1 demo accounts.
- No breaking v1.0 manual inbound/outbound flows.

## Pages

- `/erp/purchases`: add "Create inbound draft" for eligible purchase orders and show linked inbound/order fulfillment state.
- `/erp/sales`: add "Create outbound draft" for eligible sales orders, show linked outbound/order fulfillment state, and show stock shortage messages.
- `/wms/inbound`: show source as purchase order or manual creation.
- `/wms/outbound`: show target as sales order or manual creation.

## Backend Modules

- `purchase`: conversion action, cancel guard, received status recalculation.
- `sales`: conversion action, cancel guard, shipped status recalculation.
- `inboundorders`: source fields, detail/list source display, purchase sync after post.
- `outboundorders`: source fields, detail/list source display, sales sync after ship.
- `inventory`: reuse existing inventory data for sales conversion shortage checks.
- `auditlogs`: record conversion and sync events.

## Database Design

- `inbound_orders`: add `source_type`, `source_order_id`, `source_order_no`.
- `inbound_order_items`: add `source_order_item_id`, `source_line_no`.
- `outbound_orders`: add `source_type`, `source_order_id`, `source_order_no`.
- `outbound_order_items`: add `source_order_item_id`, `source_line_no`.
- `purchase_orders.status`: extend runtime states to `PARTIAL_RECEIVED` and `FULLY_RECEIVED`.
- `sales_orders.status`: extend runtime states to `PARTIAL_SHIPPED` and `FULLY_SHIPPED`.

## Status Flow

- Purchase: `DRAFT -> CONFIRMED -> PARTIAL_RECEIVED -> FULLY_RECEIVED`, with `DRAFT / CONFIRMED -> CANCELLED`.
- Sales: `DRAFT -> CONFIRMED -> PARTIAL_SHIPPED -> FULLY_SHIPPED`, with `DRAFT / CONFIRMED -> CANCELLED`.
- If a purchase/sales order has a non-canceled linked WMS order, cancel is blocked.
- Conversion creates only `DRAFT` WMS orders. It never submits, approves, posts, or ships.
- Manual WMS orders remain independent and do not sync ERP quantities.

## Permissions

- Add `PURCHASE_TO_INBOUND` for purchase-to-inbound conversion.
- Add `SALES_TO_OUTBOUND` for sales-to-outbound conversion.
- `admin`: all Sprint 2 permissions.
- `warehouse01`: purchase conversion, purchase operations, sales read.
- `cs01`: sales conversion, sales operations, purchase read.
- `observer01`: read only.

## Audit

- `ERP_PURCHASE / CREATE_INBOUND_DRAFT`
- `WMS_INBOUND / CREATE_FROM_PURCHASE`
- `ERP_SALES / CREATE_OUTBOUND_DRAFT`
- `WMS_OUTBOUND / CREATE_FROM_SALES`
- `ERP_PURCHASE / RECEIVE_STATUS_SYNC`
- `ERP_SALES / SHIP_STATUS_SYNC`

Audit payloads include source order, target WMS order, status before/after, quantity changes, and operator.

## Seed Data

- Keep Sprint 1 partners, purchases, and sales.
- Add one confirmed purchase order that can generate inbound.
- Add one partially received purchase example.
- Add one confirmed sales order with enough stock.
- Add one confirmed sales order that fails shortage conversion.
- Keep demo accounts unchanged.

## Frontend Interaction

- Conversion buttons appear only when the order status and permission allow it.
- Conversion dialog shows source order, partner, warehouse, and unfinished lines.
- Use one selected/default location per conversion for Sprint 2.
- After success, show generated WMS order number and refresh both ERP and WMS data.
- Stock shortage displays a business message with product, available quantity, requested quantity, and shortage quantity.

## E2E Plan

- admin can create an inbound draft from a confirmed purchase order.
- warehouse01 can create purchase inbound drafts.
- cs01 cannot create purchase inbound drafts.
- cs01 can create sales outbound drafts.
- warehouse01 cannot create sales outbound drafts.
- observer01 is read only.
- sales shortage conversion fails with a clear message.
- inbound post updates purchase received status.
- outbound ship updates sales shipped status.
- v1.0 manual inbound/outbound flow still passes.

## Data Quality

- Linked inbound source must point to an existing purchase order.
- Linked outbound source must point to an existing sales order.
- Linked WMS item source must point to an existing ERP item.
- Purchase received quantity cannot exceed ordered quantity.
- Sales shipped quantity cannot exceed ordered quantity.
- Fully received/shipped states must match item quantities.
- Manual WMS orders can have `source_type = MANUAL` and empty source IDs.

## Rollback

- Revert Sprint 2 code commit to restore Sprint 1 behavior.
- New DB fields are additive and do not break old code.
- Reset baseline removes Sprint 2 demo conversions and restores sample quantities.
- Manual WMS remains usable if conversion is disabled or rolled back.

## Acceptance Criteria

- Purchase conversion creates a draft inbound order and shows purchase source.
- Sales conversion creates a draft outbound order and shows sales target.
- No conversion auto-submits, auto-approves, auto-posts, or auto-ships.
- Purchase and sales quantities/statuses sync after WMS completion.
- Sales conversion blocks insufficient stock.
- Cancel rules block orders with active linked WMS documents.
- Permissions and audit events match this plan.
- Backend tests, frontend typecheck/build, E2E, data-quality, and v1.0 WMS regression pass.
