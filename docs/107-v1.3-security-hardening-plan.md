# v1.3 Sprint Q5 Security Hardening

## Summary

Sprint Q5 hardens the NovaDepot security baseline without changing business behavior,
API routes, response contracts, RBAC, database schema, AI behavior, or frontend page
workflows.

The scope is limited to JWT secret configuration and validation, database and
sensitive environment configuration hygiene, DeepSeek key checks, login rate
limiting, request body and upload size limits, CORS tightening, error response
and log masking, security regression tests, and documentation.

## Security Baseline Findings

| Area | Finding | Risk | Q5 Action |
|---|---|---|---|
| JWT | Short or placeholder secrets could be accepted after padding | High | Require non-blank secrets with at least 32 characters and reject known weak placeholders |
| Docker config | Local defaults were mixed with production-looking names | High | Keep one-click local defaults but mark them local-only and require env overrides for real deployments |
| Login | Account lock existed, but no IP + username endpoint rate limit | High | Add in-memory IP + username rate limiting for `/api/v1/auth/login` |
| Request size | Multipart and raw body size were not bounded consistently | High | Add multipart/form size config and a raw request content-length guard |
| CORS | Allowed origins were hardcoded in Java | Medium | Move origins to configuration and reject wildcard with credentials |
| Secrets | No shared masking utility for secret-like text | Medium | Add centralized masking for logs and error messages |
| Tests | Security failure paths lacked focused coverage | Medium | Add unit and MockMvc tests for Q5 behavior |

## Strict Scope

Q5 changes may touch:

- `backend/src/main/java/com/novadepot/backend/security/**`
- `backend/src/main/java/com/novadepot/backend/modules/auth/**`
- `backend/src/main/java/com/novadepot/backend/common/**`
- `backend/src/main/resources/application*.yml`
- `backend/src/test/**`
- `docker-compose.yml`
- `backend/.env.example`
- `docs/107-v1.3-security-hardening-plan.md`
- `docs/README.md`
- `README.md` if security configuration notes are needed

## Non-Goals

Q5 does not change login API paths, successful login response shape, JWT payload
fields, RBAC permissions, seed users, database schema, AI provider behavior,
fallback semantics, frontend business pages, or v1.1/v1.2/v1.2.1 flows.

Q5 does not add MFA, OAuth, SSO, captcha, v2.0, billing, or multi-tenant runtime
behavior, and it must not commit `.env`, real API keys, JWT secrets, database
passwords, tokens, build output, or test artifacts.

## Implemented Design

### JWT Secret

- `JWT_SECRET` remains the canonical configuration source.
- Secrets must be at least 32 characters.
- Known weak placeholders are rejected.
- JWT payload structure is unchanged.

### Database And Environment Configuration

- Local Docker keeps a one-command development path through explicit local-only defaults.
- Real deployments must provide their own database password and JWT secret through environment variables.
- `.env.example` contains placeholders only.

### DeepSeek Key Safety

- `AI_DEEPSEEK_API_KEY` remains the canonical key variable.
- Example files do not contain real keys.
- Secret-like values are masked before logging or returning error text.

### Login Rate Limit

- `/api/v1/auth/login` is protected by an in-memory IP + tenant + username limiter.
- Normal successful login response is unchanged.
- Rate-limit failures return a business-readable error and do not expose internal state.

### Request Size Limits

- Multipart file size, multipart request size, and Tomcat form post size are configured.
- A request body size filter rejects oversized raw requests based on `Content-Length`.
- CSV import keeps its existing API and row-level error behavior.

### CORS

- Allowed origins are configured through `app.security.cors.allowed-origins`.
- Local development keeps localhost and 127.0.0.1 origins used by Docker, Vite, and E2E.
- Wildcard origins are rejected when credentials are enabled.

### Error Response And Log Masking

- Frontend responses do not include raw stack traces.
- Secret-like text is masked in business exception logs and messages.
- Trace IDs are preserved.

## Acceptance Criteria

- JWT secret validation rejects weak placeholders and short secrets.
- `.env` remains untracked and examples contain placeholders only.
- Login rate limiting is active and normal login still works.
- Oversized requests return a business-readable error.
- CORS origins are configurable and local development origins still work.
- Error responses and logs do not expose stack traces or full secrets.
- Backend tests, frontend typecheck/build, E2E, Docker startup, reset, and data-quality checks pass or any environment-only issue is documented.

## Rollback Strategy

Each hardening item is isolated. If a regression appears, revert only that item:

- Rate limit: remove the login limiter wiring.
- Request size: remove the filter and keep configuration notes.
- CORS: restore previous hardcoded local origins.
- JWT validation: keep env-based config and relax only the dev/test validation branch.

Do not roll back Q1-Q4 completed work.
