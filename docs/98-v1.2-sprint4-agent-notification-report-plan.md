# NovaDepot v1.2 Sprint 4: Agent Patrol, Notifications, Reports, and Release Closure

> Version: v1.2-S4
> Base: `develop/v1.2`
> Theme: proactive patrol, in-app notifications, fixed reports, audit cleanup, and v1.2 closure

## Goal

Sprint 4 moves NovaDepot from passive AI Q&A to proactive operational visibility. It adds scheduled read-only patrols, in-app notifications, fixed operational reports with CSV export, audit-log retention cleanup, frontend loading/error polish, and v1.2 final release documents.

## Delivery Split

Sprint 4 is implemented as two connected slices:

- **Sprint 4A**: Agent scheduled patrol + notification center.
- **Sprint 4B**: report center + audit cleanup + frontend polish + v1.2 release closure.

The split keeps the work reviewable and preserves v1.1 business workflows plus v1.2 Sprint 1/2/3 AI capabilities.

## Strict Scope

Only implement:

- Scheduled patrols for low stock, overdue documents, and overdue tickets.
- In-app notifications with unread badge, read/read-all, and business-page jump links.
- Fixed reports: inventory turnover, inbound/outbound daily or weekly summary, purchase/sales summary, ticket efficiency, plus CSV export.
- Audit log cleanup by configurable retention days, default 90 days.
- Skeleton/error/empty-state polish for Sprint 4 pages.
- v1.2 E2E, data quality, Docker validation notes, release notes, delivery notes, acceptance checklist, and progress tracker.

Do not implement external push channels, mobile app, custom report designer, BI dashboard, notification preferences, RAG, vector DB, knowledge graph, model training, multi-tenant runtime, billing, v2.0, AI write actions, or changes to v1.1 business links and Sprint 1/2/3 AI behavior.

## Backend Design

- `modules.agent.patrol` schedules three read-only patrols:
  - `LOW_STOCK_PATROL`: scans inventory below product safety stock or default threshold.
  - `ORDER_OVERDUE_PATROL`: scans pending inbound/outbound/purchase/sales documents older than configured hours.
  - `TICKET_OVERDUE_PATROL`: scans open or processing tickets older than configured hours.
- Patrols create notifications only; they never approve, post, ship, update inventory, or send customer messages.
- `modules.notifications` becomes a real CRUD-lite module:
  - list with pagination and unread filter
  - unread count
  - detail
  - mark one read
  - mark all read
  - stable `jumpPath` generated from `bizType/bizNo`
- `modules.reports` adds four fixed read-only reports and CSV exports.
- Audit cleanup runs daily when enabled and deletes only old `audit_logs`; cleanup itself writes a new audit log row.

## Database

Migration `111-schema-v1.2-sprint4-agent-notification-report.sql` extends existing `notifications`:

- `severity VARCHAR(16) DEFAULT 'INFO'`
- `jump_path VARCHAR(255)`
- index `idx_notify_biz_receiver(tenant_id,biz_type,biz_no,receiver_user_id,notify_type)`

No report cache table is added.

## Frontend Design

- Add `/notifications` notification center.
- Add `/reports` report center with four fixed tabs.
- Add top-bar notification badge and link.
- Add sidebar entries when the user has permissions.
- Keep layout compact and operational; do not build a landing page.

## Permissions

- `NOTIFY_READ`, `NOTIFY_UPDATE`
- `REPORT_CENTER_READ`, `REPORT_EXPORT`
- `AGENT_PATROL_READ`, `AGENT_PATROL_RUN`
- `AUDIT_CLEANUP_RUN`

Admin receives all. Warehouse and CS receive relevant notification/report permissions. Observer receives read-only notification/report permissions, without export or manual patrol.
