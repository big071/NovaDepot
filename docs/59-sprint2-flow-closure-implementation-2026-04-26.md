# NovaDepot Sprint 2：流程闭环补强（2026-04-26）

## 1. 背景与目标

Sprint 1 已完成 AI/Agent/客服可用性收口，Sprint 2 聚焦“可复盘协作”：

1. 单据处理全链路可追踪（动作 + 状态 + 备注/意见）。
2. 审核分离规则继续硬落地（创建与审核分离、管理员审核兜底）。
3. 工单从“可更新”提升到“可复盘”。
4. 审计中心与业务详情联动，支持按业务编号回查。
5. 首页提供角色化待办最小闭环，支撑小团队日常分工。

## 2. 本轮范围

### 2.1 入库 / 出库闭环

1. 动作补充业务备注字段：
   - 提交备注
   - 审核意见
   - 驳回原因
   - 撤回原因
   - 作废原因
   - 过账/发运备注
2. 单据详情新增处理历史时间线，至少包含：
   - 操作时间
   - 操作人
   - 操作动作
   - 状态变化
   - 备注/意见

### 2.2 审核分离增强

1. 继续采用方案 A：
   - 仓储运营：创建、编辑、提交
   - 管理员：审核、驳回、反审核、兜底处理
   - 客服运营：不参与仓储审核
   - 观察员：只读
2. 后端继续硬校验：
   - 创建人与审核人不能相同
   - 非管理员禁止审核/反审核
3. 前端按钮与提示同步业务化表达。

### 2.3 工单闭环

1. 工单处理历史覆盖：
   - 创建工单
   - AI 建议
   - 人工接管
   - 状态变更
   - 责任人变更
   - 处理备注
   - 关闭原因
2. 客服页可识别：
   - 是否 AI 自动回复
   - 是否人工接管
   - 当前责任人
   - 下一步建议

### 2.4 审计联动

1. 审计中心按业务编号（`bizNo`）回查。
2. 单据详情/工单详情提供“查看审计记录”入口。
3. 审计记录与业务时间线动作口径保持一致。

### 2.5 首页待办（最小可用）

1. 管理员：
   - 待审核入库单
   - 待审核出库单
   - 待处理异常
   - 最近审计异常
2. 仓储运营：
   - 待提交草稿
   - 被驳回单据
   - 待执行入库/出库
   - 低库存提醒
3. 客服运营：
   - 待回复会话
   - 待处理工单
   - AI 建议待确认
4. 观察员：
   - 只读风险摘要
   - 今日业务概览

## 3. 数据与接口策略（最小改动）

1. 保持现有状态机，不引入 BPM 引擎。
2. 增加轻量“业务历史事件”表用于时间线（单据/工单复用）。
3. 关键动作继续写 `audit_logs`，并写入统一动作语义。
4. 历史与审计通过 `bizNo` + 资源类型联动回查。

## 4. 页面交互原则

1. 单据详情优先展示“状态 + 时间线 + 业务备注”，不先抛技术字段。
2. 工单详情优先展示“发生了什么、谁处理过、下一步做什么”。
3. 原始 JSON 仅作为折叠技术详情展示。
4. 无权限反馈使用业务化提示语。

## 5. 验收标准

1. 入库单详情可见完整处理历史与备注/意见。
2. 出库单详情可见完整处理历史与备注/意见。
3. 管理员可审核/驳回；仓储运营不能审核自己创建单据。
4. 非管理员执行审核类动作后端拒绝，前端提示清晰。
5. 工单详情可见状态、责任人、备注、AI 建议、人工接管历史。
6. 客服页可区分 AI 自动回复与人工接管状态。
7. 审计中心可按业务编号回查。
8. 单据/工单详情可跳转或打开相关审计记录。
9. 首页按角色展示待办区。
10. 角色权限不回退。
11. Docker 本地运行不受影响。

## 6. 风险与回滚

1. 风险：历史事件新增写入可能影响旧数据展示。
   - 回滚：历史表读取降级为仅审计回放，不影响主流程。
2. 风险：权限提示前后口径不一致。
   - 回滚：保留后端硬校验，前端提示回退为统一拒绝文案。
3. 风险：种子账号与角色映射不一致。
   - 回滚：恢复旧种子脚本并保留管理员兜底登录。

## 7. 本轮不做（严格）

1. FAQ/SOP 后台化与知识库版本管理（Sprint 3）。
2. 多租户、计费、采购/销售/财务模块扩展。
3. 复杂流程设计器/BPM 引擎。
4. DeepSeek 作为强依赖。
5. 新增独立业务中心页面。

## 8. 后续待办（仅记录，不在本轮实现）

1. Sprint 3：FAQ/SOP 可维护后台（版本、发布、回滚）。
2. Sprint 3：规则配置中心（客服规则、Agent 策略、阈值治理）。
3. Sprint 3：更细粒度的历史筛选与批注能力。

## 9. 实施前差距复盘（2026-04-26）

1. 入库/出库后端已写入审计动作，但详情页仍以“数据列表”为主，未形成业务可复盘时间线。
2. 提交/审核/驳回/撤回/作废/过账与发运虽可传 `note`，但缺少动作级业务语义字段展示。
3. 工单接口当前仍有 mock 返回，历史链路不完整，无法满足可复盘协作要求。
4. 审计中心支持按 `bizNo` 筛选，但单据/工单详情未提供联动入口。
5. 首页已有角色化快捷任务，但缺少 Sprint 2 要求的角色化待办区块。
6. 多个业务页面存在中文乱码文本，需按 AGENTS.md 文本完整性规则修复。

## 10. Sprint 2 严格边界（执行约束）

1. 只做单据、工单、审核、备注、历史、审计联动、首页待办收口。
2. 保持状态机，不引入 BPM 或流程设计器。
3. 保持单租户和 Docker 本地可运行，不改技术栈。
4. 不做 Sprint 3 的 FAQ/SOP 后台化、知识库版本管理、规则中心。
5. 不新增独立业务中心页，仅在现有 `/dashboard`、详情页、审计页补强。

## 11. 本轮设计口径（实现约束）

### 11.1 单据闭环口径

1. 入库/出库详情统一展示：
   - 当前状态及下一步建议。
   - 处理历史时间线（时间、操作人、动作、状态变化、备注/意见）。
   - 审计联动入口（按 `bizNo` 回查）。
2. 动作备注语义统一：
   - `submit`: 提交备注
   - `approve`: 审核意见
   - `reject`: 驳回原因
   - `withdraw`: 撤回原因
   - `cancel`: 作废原因
   - `post/ship`: 过账/发运备注

### 11.2 审核分离口径

1. 后端硬校验：
   - 非管理员拒绝审核/驳回/反审核类动作。
   - 创建人与审核人不得为同一人。
2. 前端行为同步：
   - 按权限与角色隐藏/禁用按钮。
   - 无权限时展示业务化中文提示，不暴露技术栈错误。

### 11.3 工单闭环口径

1. 工单状态仅收口为：`OPEN`、`PROCESSING`、`RESOLVED`、`CLOSED`。
2. 工单处理历史覆盖：
   - 创建工单
   - AI 建议
   - 人工接管
   - 状态变更
   - 责任人变更
   - 处理备注
   - 关闭原因
3. 客服页必须可见：
   - 是否发生 AI 自动回复
   - 是否发生人工接管
   - 当前责任人
   - 下一步建议

### 11.4 审计联动口径

1. 审计中心继续按 `bizNo` + 资源类型查询。
2. 详情页“查看审计记录”统一跳转 `/system/audit-center?bizNo=...&resourceType=...`。
3. 审计动作文案与时间线动作文案保持同一中文口径。

### 11.5 首页待办口径

1. 管理员：首页展示待审核入库、待审核出库、待处理异常、最近审计异常。
2. 仓储运营：首页展示待提交草稿、被驳回单据、待执行入库/出库、低库存提醒。
3. 客服运营：首页展示待回复会话、待处理工单、AI 建议待确认。
4. 观察员：首页展示只读风险摘要、今日业务概览。

## 12. 数据与接口最小改造策略

1. 保留 `audit_logs` 作为单据时间线主来源。
2. 新增轻量“业务历史事件”表，记录工单与协作动作，字段至少包含：
   - `resource_type`
   - `resource_id`
   - `biz_no`
   - `action`
   - `action_label`
   - `status_from`
   - `status_to`
   - `note`
   - `operator_id`
   - `operator_name`
   - `occurred_at`
3. 客服工单接口由 mock 改为 MySQL 持久化，历史事件与审计同步写入。
4. 新增或补齐详情接口返回结构：`base + timeline + auditQuery`。

## 13. Sprint 2 验证步骤（对齐 Sprint 1 验证方式）

1. 以管理员创建并处理入库单，验证详情时间线与备注意见完整展示。
2. 以管理员创建并处理出库单，验证详情时间线与备注意见完整展示。
3. 以仓储运营账号尝试审核动作，验证后端拒绝并前端显示业务化提示。
4. 以客服运营账号执行工单状态、责任人、备注更新，验证时间线落库可回看。
5. 在客服页触发客户消息自动回复，再转人工接管，验证 AI/人工状态可区分。
6. 在单据和工单详情点击“查看审计记录”，验证审计中心按业务编号回查成功。
7. 使用 4 类角色登录首页，验证待办区块内容按角色切换。
8. 按 Docker Compose 本地启动，验证后端、前端、MySQL、Redis 联调可用。
