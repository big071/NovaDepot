# NovaDepot 培训与演示体系完善 Sprint（2026-04-22）

## 1. 目标
让 NovaDepot 不仅“可运行”，还可用于培训、答辩、售前演示与交付说明，确保不同角色能快速理解系统价值与操作边界。

## 2. 本轮新增与调整
1. 夜间一致性任务新增 `data-quality-check.ps1`，形成自动回归基线。
2. 低库存口径（安全库存解析）下沉为共享服务，统一仪表盘、库存预警、AI 建议逻辑。
3. AI 补货建议新增“事实引用校验”规则：建议中的 SKU 必须存在且可追溯到库存记录。

## 3. 四套业务场景（培训版脚本）

### 3.1 场景 A：仓库日常入库作业链路
1. 参与角色：`warehouse_manager`、`operator`
2. 起始数据：`IN-SCN-2026042201`（DRAFT）、明细商品 `300711`
3. 页面路径：`/dashboard` -> `/wms/inbound` -> `/wms/inventory`
4. 步骤说明：
   1. 编辑入库草稿（仓库、商品、库位、数量）。
   2. 提交单据（`DRAFT -> SUBMITTED`）。
   3. 审核单据（`SUBMITTED -> APPROVED`）。
   4. 过账单据（`APPROVED -> POSTED`）。
5. 截图点：`SCN-A-01` ~ `SCN-A-04`
6. 预期结果：
   1. 单据状态推进正确。
   2. 库存增加，库存流水出现对应 `biz_no`。
7. 常见错误与解释：
   1. 错误：草稿字段不完整直接提交失败。解释：后端状态机与字段校验拦截。
   2. 错误：未审核直接过账失败。解释：必须先到 `APPROVED`。

### 3.2 场景 B：销售出库与低库存预警链路
1. 参与角色：`warehouse_manager`、`admin`
2. 起始数据：`OUT-SCN-2026042202`（SUBMITTED）、低库存 SKU 样本
3. 页面路径：`/wms/outbound` -> `/wms/inventory` -> `/dashboard`
4. 步骤说明：
   1. 审核出库单（`SUBMITTED -> APPROVED`）。
   2. 发运出库单（`APPROVED -> SHIPPED`）。
   3. 查看库存预警与流水扣减。
5. 截图点：`SCN-B-01` ~ `SCN-B-04`
6. 预期结果：
   1. 状态推进成功。
   2. 库存扣减生效。
   3. 低库存统计与仪表盘一致。
7. 常见错误与解释：
   1. 错误：库存不足时发运失败。解释：后端防止负库存。
   2. 错误：低库存列表与预期不一致。解释：口径为“商品安全库存优先，默认阈值兜底”。

### 3.3 场景 C：客服建单与工单回查链路
1. 参与角色：`cs_agent`
2. 起始数据：会话 `CS-SCN-*`、工单 `TCK-SCN-*`、FAQ `FAQ-SCN-*`
3. 页面路径：`/cs/workspace`（可选回查：`/system/audit-center`）
4. 步骤说明：
   1. 选择会话并回复（人工/AI）。
   2. 从会话创建工单，填写优先级与问题说明。
   3. 更新工单状态、责任人、处理备注。
   4. 按会话号或工单号回查处理过程。
5. 截图点：`SCN-C-01` ~ `SCN-C-04`
6. 预期结果：
   1. 会话与工单双向可追溯。
   2. 状态与责任人更新可回显。
   3. FAQ 支持标准化答复。
7. 常见错误与解释：
   1. 错误：未选会话直接建单失败。解释：工单必须绑定有效会话。
   2. 错误：非法状态值更新失败。解释：仅支持 `OPEN/PROCESSING/RESOLVED/CLOSED`。

### 3.4 场景 D：管理层仪表盘 + AI 补货建议链路
1. 参与角色：`admin`、`viewer`
2. 起始数据：当日入出库样本、低库存样本、AI 历史会话
3. 页面路径：`/dashboard` -> `/ai/enterprise` -> `/wms/inventory`
4. 步骤说明：
   1. 查看 `todayInbound/todayOutbound/lowStockCount`。
   2. 在 AI 页面发起补货建议咨询（推荐问题或自定义）。
   3. 对照库存页面核验建议是否引用真实 SKU 与库存事实。
5. 截图点：`SCN-D-01` ~ `SCN-D-05`
6. 预期结果：
   1. AI 建议包含“结论 + 依据 + 建议动作”。
   2. 建议中的 SKU 可追溯到库存记录。
   3. 指标、明细、建议口径一致。
7. 常见错误与解释：
   1. 错误：AI 建议过于泛化。解释：提问需带业务目标（补货周期、风险优先级）。
   2. 错误：建议 SKU 无法追溯。解释：触发事实引用校验失败，需检查样本数据与口径配置。

## 4. 角色上手路径

### 4.1 admin
1. 先看什么：仪表盘总览、审计中心、用户管理。
2. 常用操作：看指标、查审计、重置用户密码、核验口径。
3. 不该做什么：绕过流程改状态；高峰时段重置演示数据。
4. 无权限时会看到什么：403 或页面内权限提示。

### 4.2 warehouse_manager
1. 先看什么：低库存预警、入库/出库待处理。
2. 常用操作：提交与审核入库，审核与发运出库。
3. 不该做什么：在非草稿状态强行改单。
4. 无权限时会看到什么：按钮受限或接口返回权限/状态提示。

### 4.3 operator
1. 先看什么：入库/出库草稿与待处理单。
2. 常用操作：维护草稿明细、提交、核对库存流水。
3. 不该做什么：执行超出职责的审核/管理动作。
4. 无权限时会看到什么：按钮禁用或后端拒绝提示。

### 4.4 cs_agent
1. 先看什么：会话列表、当前会话工单、FAQ。
2. 常用操作：回复会话、创建工单、更新状态与责任人。
3. 不该做什么：绕过工单流程直接口头关闭问题。
4. 无权限时会看到什么：工单更新被拒绝并提示原因。

### 4.5 viewer
1. 先看什么：仪表盘、库存视图、AI 历史建议。
2. 常用操作：只读查看指标、列表、建议结果。
3. 不该做什么：执行写操作（入出库、工单更新等）。
4. 无权限时会看到什么：写接口被拒绝并提示权限不足。

## 5. 三类讲解顺序

### 5.1 演示顺序（业务闭环导向）
1. 仪表盘总览（价值定位）。
2. 场景 A 入库链路（补货入仓）。
3. 场景 B 出库 + 低库存（履约与风险）。
4. 场景 C 客服工单闭环（服务质量）。
5. 场景 D AI 建议与事实对照（智能增强）。

### 5.2 答辩顺序（口径与可验证导向）
1. 指标口径说明（仪表盘、低库存规则）。
2. 一致性校验能力（release + data-quality-check）。
3. 状态机与权限边界（入出库、工单、viewer 只读）。
4. AI 事实引用校验（建议可追溯）。
5. 运维交付能力（重置、备份、回滚）。

### 5.3 售前顺序（价值与落地导向）
1. 角色化价值：老板看经营、仓管看效率、客服看闭环。
2. 首页快捷任务与角色引导卡。
3. 入/出库效率与低库存风险联动。
4. 客服工单 + FAQ 标准化。
5. AI 辅助决策与可审计复盘。
