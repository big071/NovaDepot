# NovaDepot Sprint 1 验收热修记录（2026-04-26）

## 1. 发现的问题
在执行 `scripts/ops/data-quality-check.ps1` 时，低库存一致性校验出现：
- API `lowStockCount = 42`
- 脚本事实计算 `sql = 39`

这不是业务页面回退，而是验收脚本中的“低库存事实口径”存在文本解析链路问题。

## 2. 根因
原脚本先把 `products.spec` 中的中文规格文本取回 PowerShell，再在脚本侧解析“安全库存=XX”。
这条链路会受到控制台/进程输出解码影响，导致中文规则文本在脚本侧可能无法稳定命中正则，进而错误回退到默认阈值 10。

## 3. 修复方式
本轮不改 Sprint 2/3 范围，只做 Sprint 1 验收热修：
1. 保留系统现有低库存业务逻辑。
2. 将 `data-quality-check.ps1` 的低库存事实计算改为直接在 MySQL 8 中完成。
3. 使用 MySQL 的 `regexp_substr` + `regexp_replace` 在数据库 UTF-8 数据层提取“安全库存=XX”中的阈值。
4. 若未配置明确阈值，则继续使用默认阈值 10。

## 4. 影响范围
- `scripts/ops/data-quality-check.ps1`
- 验收链路中的低库存一致性校验

未改动：
- AI 助手页面逻辑
- Agent Center 页面逻辑
- 客服工作台页面逻辑
- 单据/工单流程逻辑

## 5. 预防说明
后续凡是涉及中文业务文本规则的校验：
1. 优先在数据库或后端 UTF-8 逻辑层完成事实判断。
2. 不再依赖 PowerShell/终端输出链路去解析中文规则文本。
3. 若必须跨进程读取中文文本，需显式校验编码和回读结果。
