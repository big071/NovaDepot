# NovaDepot v1.0 演示走查指南

## 1. 演示前准备

### 1.1 启动环境

```bash
docker compose up -d
./scripts/ops/reset-commercial-baseline.ps1
./scripts/ops/data-quality-check.ps1
```

预期：4 个容器运行中，数据质量 ALL PASS。

### 1.2 浏览器准备

打开两个浏览器（或两个无痕窗口），分别：
- **窗口 A（管理员）**：`admin / admin123`
- **窗口 B（客服）**：`cs01 / pass123`

## 2. 演示路线（约 15 分钟）

### 第 1 站：库存概览（1 分钟）

**用户**：admin 登录，进入仪表盘 `/dashboard`

**演示点**：
1. 展示 KPI 卡片（总库存、低库存产品数、今日入库/出库）
2. 点击"低库存产品"进入库存列表 → 展示红色预警行

**说话要点**：
"这是仓库仪表盘，可以看到实时 KPI。标记红色的产品库存低于安全线，需要关注补货。"

---

### 第 2 站：AI 助手（2 分钟）

**用户**：切换到 AI 助手 `/ai/enterprise`

**演示点**：
1. 输入"怎么入库" → AI 回复含 FAQ # 和 SOP # 引用
2. 点击引用链接 → FAQ 详情弹出
3. 输入"库存补货" → 触发 Agent 执行
4. 查看历史消息列表 → 可回溯

**说话要点**：
"AI 助手回答流程问题时，会引用知识库中的 FAQ 和 SOP，展示引用来源。遇到任务类问题，如补货建议，会自动触发 Agent 进行分析。"

---

### 第 3 站：Agent 中心（2 分钟）

**用户**：切换到 Agent Center `/agent/center`

**演示点**：
1. 展示 Agent 执行历史列表
2. 点开最近一次"低库存分析"结果
3. 展示摘要卡片（紧急 3 个、预警 7 个）
4. 展示表格明细（产品名、当前库存、安全线、补货建议）
5. 展示"执行依据"（规则 low_stock_threshold=50）
6. 展示"建议动作"

**说话要点**：
"Agent 自动执行库存分析，生成报告卡片、明细表格、执行依据和补货建议。每次执行都记录在案，可随时回溯。"

---

### 第 4 站：入库流程（2 分钟）

**用户**：以 admin 切换到入库单列表页 `/wms/inbound`

**演示点**：
1. 展示入库单列表（含不同状态）
2. 点开一条"待审核"入库单 → 点击"审核通过"
3. 状态变更 → 审计日志自动记录

**说话要点**：
"入库需要仓储运营创建、管理员审核、再执行。审核通过后库存不立即增加，执行完成后才正式入库。每步操作都记录审计日志。"

---

### 第 5 站：客服工作台 + 知识维护（3 分钟）

**用户**：切换到窗口 B（cs01），进入客服工作台 `/cs/workspace`

**演示点 1 - 客服会话：**
1. 展示会话列表
2. 点击一个活跃会话 → 展示历史消息
3. 输入客户咨询 → AI 在建议框中自动生成候选回复
4. 点击"查看依据" → 弹出 FAQ/规则引用详情
5. 点击"采用建议"或手动编辑后发送
6. 点击"创建工单" → 选择分类，创建工单

**演示点 2 - 知识沉淀（从工单）：**
7. 切换到工单列表 → 点开工单详情
8. 点击"沉淀为 FAQ"
9. 自动填充问题 → 编辑答案 → 保存为草稿
10. 回到 FAQ 列表 → 草稿可见，状态为"草稿"

**演示点 3 - 知识维护：**
11. 在客服工作台内切换到"知识维护"
12. 展示 FAQ 列表（含已启用 + 草稿）
13. 编辑一条草稿 → 点击"确认启用" → 草稿变为已启用
14. 停用一条 FAQ → 状态变为已停用
15. 同样操作 SOP 列表

**说话要点**：
"客服工作台集成了 AI 建议回复和知识维护。AI 会根据客户消息匹配 FAQ/SOP/规则自动生成建议，标注引用来源。客服确认后发送。对于典型案例，客服可以一键将工单沉淀为 FAQ 或 SOP 草稿，经确认后正式生效。"

---

### 第 6 站：权限控制 + 规则配置（2 分钟）

**演示点 1 - 非管理员越权：**
1. 以 cs01 访问规则配置入口
2. 规则值编辑按钮置灰，hover 显示 tooltip"仅管理员可修改业务规则"
3. 切换到窗口 A（admin）
4. 规则配置入口可见可编辑
5. 修改 `low_stock_threshold` 从 50 到 40 → 审计日志记录

**演示点 2 - 页面级权限：**
6. 以 cs01 访问 `/system/audit-center` → 重定向到 403 页面
7. 以 admin 访问同一 URL → 正常显示审计中心

**说话要点**：
"规则配置仅管理员可修改。非管理员看到的是置灰状态，后端 API 也会校验权限，返回 403。审计中心也只有管理员可以访问。这保证了操作安全性和可追溯性。"

---

### 第 7 站：审计中心（2 分钟）

**用户**：以 admin 进入审计中心 `/system/audit-center`

**演示点**：
1. 审计日志列表展示
2. 按模块筛选 `knowledge` → 显示 FAQ/SOP 的变更记录
3. 按操作人筛选 → 按时间范围筛选
4. 点开一条 FAQ 变更记录 → 弹窗显示变更前/变更后 JSON diff

**说话要点**：
"审计中心记录所有关键操作的变更历史。可以按模块、操作人、时间范围筛选。每条记录包含具体的变更前后数据，支持完整的合规审计。"

---

## 3. 可选演示场景

### 场景 A：出库库存不足

1. 创建出库单，数量远超库存
2. 审核通过 → 发运执行
3. 系统提示"库存不足，无法发运"
4. 展示优雅的错误提示

### 场景 B：Agent 任务手动触发

1. 在 Agent Center 点击"执行异常巡检"
2. 等待执行完成
3. 展示巡检结果（异常项列表）

### 场景 C：客服工单闭环

1. 客服接收客户消息
2. AI 建议回复 → 采用
3. 创建工单
4. 在工单中备注处理方案
5. 关闭工单
6. 沉淀为 SOP 草稿

## 4. 演示后清理

```bash
docker compose down
```

（数据已通过 baseline 重置，无需额外清理）

## 5. 常见演示问题预案

| 问题 | 预案 |
|------|------|
| Docker 服务未启动 | 提前 5 分钟启动，验证 `docker compose ps` |
| 页面加载慢 | 等待 30 秒让 Spring Boot 完全启动 |
| AI 回复无引用 | 确认种子 FAQ 数据已导入，运行 `data-quality-check` |
| Agent 无历史 | 通过 AI 助手触发一次"库存补货"生成结果 |
| 权限控制不生效 | 确认以 cs01 而非 admin 登录，确认 Token 正确 |
| 审计日志空 | 先操作一次 FAQ 编辑/启用，再查看 |
| 中文字体乱码 | 确认 MySQL charset = utf8mb4，重启数据重置 |
