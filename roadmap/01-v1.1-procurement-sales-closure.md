# v1.1 —— 进销存闭合 + 运营刚需补全

> STATUS: PLANNED
> 预估周期：6-8 周
> 前置条件：v1.0 已完成并交付

---

## 1. 版本定位

**让 NovaDepot 从一个"智能仓库操作台"升级为"轻量进销存一体化系统"。**

v1.0 的 WMS 层只覆盖了库存和入库/出库操作，采购和销售完全在线下。这意味着：
- 入库单创建后，系统不知道这批货是从哪个供应商采购的
- 出库单创建后，系统不知道这批货是卖给哪个客户的
- 库存成本、应收应付完全不可见

v1.1 的目标是打通"采购 → 入库 → 库存 → 出库 → 销售"这一条最小业务链路，让系统成为仓库团队真正能用的日常工具。同时补上仓库运营的几个物理刚需——盘点、CSV导入、打印、数据备份。

---

## 2. 要解决的核心矛盾

| 矛盾 | 现状 | 目标 |
|------|------|------|
| 入库/出库单与上下游脱节 | 入库单无采购来源；出库单无销售去向 | 采购单可转入库、销售单可转出库 |
| 仓库无法盘点 | 无盘点功能，账实差异不可发现 | 盘点单创建 → 差异确认 → 库存调整 |
| 大量历史数据无法迁入 | 无批量导入，只能逐条手动录入 | CSV 批量导入产品/库存/往来单位 |
| 出库无物理输出 | 出库审核后无拣货单/标签可打印 | 浏览器打印模板 |
| 数据无保障 | 无备份机制 | mysqldump 定时备份脚本 |
| 前端组件复用度低 | 每个页面独立实现 Table/Dialog/Status | 共用组件底座（DataTable 等 7 组件） |
| 多租户改造越晚越痛 | 所有业务表无 tenant_id 列 | 提前加列，不启用过滤 |

## 3. 功能范围

### 3.1 采购管理

| 能力 | 说明 |
|------|------|
| 采购单 CRUD | 创建采购单：往来单位（供应商）、预计到货日期、商品明细（产品+数量+单价） |
| 采购单状态 | DRAFT → CONFIRMED → PARTIAL_RECEIVED → FULLY_RECEIVED → CANCELLED |
| 采购单→入库 | 已确认采购单可创建关联入库单（带入产品和数量，人工确认） |
| 采购列表 | 支持按状态/往来单位/日期范围筛选，DataTable 分页 |

**不做什么**：
- 不做采购申请/审批流（审批留到 v2.0+）
- 不做采购退货（留到 v1.2+）
- 不做比价/询价

### 3.2 销售管理

| 能力 | 说明 |
|------|------|
| 销售单 CRUD | 创建销售单：往来单位（客户）、预计发货日期、商品明细（产品+数量+单价） |
| 销售单状态 | DRAFT → CONFIRMED → PARTIAL_SHIPPED → FULLY_SHIPPED → CANCELLED |
| 销售单→出库 | 已确认销售单可创建关联出库单（带入产品和数量，检查库存是否充足） |
| 销售列表 | 支持按状态/往来单位/日期范围筛选，DataTable 分页 |

**不做什么**：
- 不做销售退货（留到 v1.2+）
- 不做销售报价/合同

### 3.3 往来单位管理（供应商/客户合并）

> **设计决策**：v1.0 团队规模 3-15 人，供应商和客户重合度可能很高（如既是供应商又是客户的贸易伙伴）。合并为"往来单位"并用 `type` 字段区分，减少 1 套 CRUD。

| 能力 | 说明 |
|------|------|
| 往来单位 CRUD | 名称、类型（SUPPLIER / CUSTOMER / BOTH）、联系人、电话、地址 |
| 列表筛选 | 按类型、名称搜索 |
| 关联查询 | 查看该单位的采购单/销售单历史 |

### 3.4 应收应付台账

| 能力 | 说明 |
|------|------|
| 应付台账 | 采购单确认后自动生成应付记录；入库完成后更新应付金额 |
| 应收台账 | 销售单确认后自动生成应收记录；出库完成后更新应收金额 |
| 付款/收款登记 | 手动登记付款/收款，核销应收应付 |
| 状态 | UNPAID → PARTIALLY_PAID → PAID |
| 汇总视图 | 按往来单位汇总应收/应付余额 |

**不做什么**：
- 不做发票管理
- 不做账期/账龄分析
- 不做自动对账

### 3.5 库存盘点 ⚠️ 新增

> **这是仓库管理最基础的闭环操作，v1.0 缺失是严重缺陷。**

| 能力 | 说明 |
|------|------|
| 盘点单创建 | 选择仓库、盘点范围（全部/按产品分类/指定产品） |
| 盘点录入 | 逐条录入实际数量，系统自动对比账面数量，计算差异 |
| 差异确认 | 差异明细列表：产品/账面数/实盘数/差异数；逐条确认或全部确认 |
| 库存调整 | 确认后自动生成库存调整记录（入库调整/出库调整），更新库存 |
| 盘点状态 | DRAFT → IN_PROGRESS → DIFF_REVIEW → COMPLETED |
| 盘点历史 | 按仓库/日期范围查看历史盘点记录 |

**不做什么**：
- 不做盲盘模式（先不显示账面数）
- 不做 PDA/扫码枪盘点（留到移动端版本）
- 不做循环盘点计划

### 3.6 CSV 批量导入 ⚠️ 从 v1.2 提前

> **真实团队使用的前置条件——没有导入能力，初始数据录入成本太高。**

| 能力 | 说明 |
|------|------|
| 产品批量导入 | CSV 模板下载 + 上传解析 + 校验报告 + 逐条导入 |
| 库存初始导入 | 模板：仓库编码 + 产品编码 + 数量 + 批次号（可选） |
| 往来单位导入 | 模板：名称 + 类型 + 联系人 + 电话 + 地址 |
| 校验报告 | 格式错误行号 + 字段级错误提示；出错行跳过，正确行导入 |
| 重复处理 | SKU 重复 → 跳过并提示；可选择"覆盖更新"模式 |

**CSV 模板格式**：
- 第一行为列标题（中文）
- 编码统一用 UTF-8
- 日期格式：yyyy-MM-dd
- 数字不带千分位分隔符

**不做什么**：
- 不做 Excel（.xlsx）导入（CSV 够用，避免 poi 依赖）
- 不做导出（导出留到 v1.2 报表中心）
- 不做导入历史/回滚

### 3.7 打印模板 ⚠️ 新增

> **仓库出库的物理闭环——审核完出库单后需要打印拣货单/出库单。**

| 能力 | 说明 |
|------|------|
| 入库单打印 | 浏览器打印：单号、日期、往来单位、商品明细、签字区 |
| 出库单打印 | 浏览器打印：单号、日期、往来单位、商品明细（含库位）、签字区 |
| 拣货单打印 | 按库位排序的商品清单，含拣货确认勾选框 |
| 打印样式 | `@media print` CSS，隐藏导航栏/按钮，A4 纸张适配 |

**实现方式**：纯前端 CSS `@media print`，不依赖第三方打印库。

**不做什么**：
- 不做标签打印机适配（如斑马打印机）
- 不做自定义打印模板设计器
- 不做批量打印

### 3.8 数据备份 ⚠️ 新增

> **运维底线——没有备份，发生数据丢失就是灾难。**

| 能力 | 说明 |
|------|------|
| 备份脚本 | `scripts/ops/backup.sh`：mysqldump + 压缩 + 保留最近 N 天 |
| 定时任务 | 通过 cron 或 Docker 定时任务容器每日凌晨执行 |
| 备份目录 | `./backups/` 挂载到宿主机 |
| 保留策略 | 保留最近 7 天日备份 + 最近 4 周周备份 |
| 手动备份 | 管理员可在系统设置页面触发即时备份 |
| 备份列表 | 查看已有备份文件列表（文件名、大小、时间） |

**不做什么**：
- 不做自动恢复（恢复操作由运维手动执行）
- 不做异地备份/云存储备份
- 不做增量备份

### 3.9 共用组件底座 ⚠️ 保留原规划

> **v1.0 前端每个页面独立实现，大量重复代码。v1.1 提取共用组件，后续所有页面复用。**

| 组件 | 说明 |
|------|------|
| DataTable | 通用数据表格：分页、排序、列配置、loading/empty/error 状态 |
| ConfirmDialog | 通用确认弹窗：标题 + 内容 + 确认/取消 |
| StatusBadge | 状态标签：颜色映射（DRAFT=灰 / CONFIRMED=蓝 / COMPLETED=绿 / CANCELLED=红） |
| SearchForm | 通用搜索表单：多字段 + 搜索/重置按钮 |
| PageHeader | 页面标题栏：标题 + 面包屑 + 操作按钮 slot |
| EmptyState | 空状态引导：图标 + 提示文字 + 操作按钮 |
| ErrorState | 错误状态：错误信息 + 重试按钮 + 错误详情折叠 |

**新增文件清单**：
```
frontend-vue/src/components/shared/
├── DataTable.vue
├── ConfirmDialog.vue
├── StatusBadge.vue
├── SearchForm.vue
├── PageHeader.vue
├── EmptyState.vue
└── ErrorState.vue
```

### 3.10 tenant_id 预留 ⚠️ 从 v2.0 提前

> **现在加：ALTER TABLE 加列（默认 NULL）→ 零风险。v2.0 加：数据迁移 + 回填 → 高风险。这个技术债现在不还以后更贵。**

| 步骤 | 说明 |
|------|------|
| 所有业务表加 `tenant_id` | BIGINT DEFAULT NULL，不加 NOT NULL 约束 |
| 索引 | `tenant_id` 加普通索引（不启用过滤时不生效） |
| 不启用拦截器 | MyBatis-Plus 全局过滤器不注入 |
| 不修改现有查询 | 所有 SQL 无需加 tenant_id 条件 |

**受影响的表**：
```
products, product_categories, warehouses, inventory, inventory_logs,
inbound_orders, inbound_items, outbound_orders, outbound_items,
purchase_orders, purchase_items, sale_orders, sale_items,
partners, payables, receivables,
tickets, ticket_messages, faq, faq_categories,
ai_conversations, ai_messages, agent_tasks, agent_task_runs,
audit_logs, notifications, stock_take_orders, stock_take_items
```

### 7.2 共用组件设计原则

1. 所有新增页面（采购/销售/往来单位/应收应付/盘点）**强制使用共用组件**
2. 现有页面（产品/库存/入库/出库）**逐步迁移**到共用组件
3. 新页面代码量目标：每个页面 200-300 行（含 template + script + style），不重复造轮子
4. DataTable 支持后端分页/排序，Loading/Empty/Error 三种状态覆盖

## 8. 验收标准

1. 采购单可创建，确认后可创建关联入库单，入库后采购单状态正确流转。
2. 销售单可创建，确认后可创建关联出库单（库存不足时阻止），出库后销售单状态正确流转。
3. 采购单确认后自动生成应付记录；销售单确认后自动生成应收记录。
4. 付款/收款登记后可核销应收应付，余额正确。
5. 盘点单可创建，录入实盘数后系统自动计算差异，确认后库存正确调整。
6. 产品/库存/往来单位支持 CSV 批量导入，校验报告反馈具体错误行和字段。
7. 入库单详情页可打印，隐藏导航栏，A4 纸适配。
8. 出库单详情页可打印，含库位信息。
9. `scripts/ops/backup.sh` 可正常执行并生成压缩备份文件。
10. 所有新增表 + 全部现有业务表包含 `tenant_id` 列（默认 NULL，不启用过滤）。
11. 共用组件（DataTable 等 7 个）在采购/销售页面正确使用。
12. 现有 E2E 测试不回退。
13. Docker 一键启动不受影响。

## 10. 风险与应对

| 风险 | 应对 |
|------|------|
| 采购→入库→应收应付链路长，状态机复杂 | 用枚举 + 状态流转表严格控制，每个状态变更写审计日志 |
| CSV 导入格式兼容性 | 仅支持 UTF-8 CSV，文档写明格式要求；提供模板下载 |
| 盘点期间并发修改库存 | 盘点开始后冻结该仓库的入库/出库操作（或标记为"盘点中"阻止操作） |
| tenant_id 加列表数量大 | 按模块分批执行，先加核心表再扩展表 |
| 共用组件迁移可能破坏现有页面 | 新页面先用共用组件，现有页面渐进迁移，每次迁移跑 E2E |
| 打印样式浏览器兼容 | 优先适配 Chrome/Edge，Firefox 次之 |
