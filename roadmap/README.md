## 关键设计决策

### 为什么商业化放在 v2.0 而非 v1.1
1. **产品不够卖** — v1.0 只有 WMS，v1.1 进销存闭环 + v1.2 DeepSeek 智能后才形成完整竞争力
2. **AI 是付费锚点** — 商业化前必须先有真正的智能能力，而不是关键词匹配
3. **先跑通再收费** — v1.0-v1.2 打磨产品，v2.0 验证商业模型

### 为什么 DeepSeek 而非其他 LLM
1. **成本极低** — DeepSeek Chat 定价 ¥1/百万 tokens，是 GPT-4o 的 1/30
2. **中文理解优秀** — 专注中文场景的仓库物流术语
3. **Function Calling 兼容 OpenAI** — 零迁移成本的工具调用协议
4. **国家合规** — 数据不出境，适合国内企业用户
5. **开源模型可私有化** — 企业版后期可部署私有化 DeepSeek 实例

### 为什么不用 RAG / 向量数据库
- v1.0-v2.0 阶段，Function Calling + 10 个工具函数 + 知识库表查询已覆盖 90% 场景
- RAG 引入 LangChain/Milvus 会大幅增加系统复杂度（v3.0+ 再评估）
- 当前 FAQ 知识库用 MySQL + 关键词匹配即可
