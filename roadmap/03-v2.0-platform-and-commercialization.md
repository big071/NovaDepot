# v2.0 —— 平台化 + SaaS 商业化

> STATUS: PLANNED
> 预估周期：10-14 周
> 前置条件：v1.2 DeepSeek 智能核心完成（Function Calling + 流式输出 + Agent 巡检是商业化的卖点基础）

---

## 1. 版本定位

**从"单租户单体应用"升级为"多租户 SaaS 平台"，具备：**
- **按团队注册/试用**（免费试用 + 付费订阅）
- **多仓库支持**（一个团队管理多个仓库）
- **数据安全隔离**（tenant_id 行级隔离，已在 v1.1 预埋）
- **用量统计 + 计费**（按仓库数/用户数/AI 调用次数分级）
- **管理后台**（运营视角：租户管理 + 用量监控 + 系统健康）

### 商业化为什么放在 v2.0 而非 v1.1

| 原因 | 说明 |
|------|------|
| 产品不够卖 | v1.0 只有 WMS，太单薄。v1.1 进销存闭环 + v1.2 DeepSeek 智能后才有说服力 |
| 没有多租户底座 | v1.1 预埋 `tenant_id` 但未启用，v2.0 正式启用 |
| 卖 AI 需要先有 AI | v1.2 的 Function Calling + DeepSeek 实时推理是核心付费卖点 |
| 先跑通再收费 | v1.0-v1.2 是功能打磨阶段，证明产品有价值再商业化 |

## 2. 核心矛盾

| 矛盾 | 现状 | 目标 |
|------|------|------|
| 单仓库不可扩展 | 系统硬编码 1 个仓库 | 多仓库管理，每个仓库独立库存/出入库 |
| 单租户不能卖 | 所有用户共享数据空间 | tenant_id 行级隔离，团队间完全隔离 |
| 无计费体系 | 无法区分免费/付费用户 | 套餐分级（免费版/专业版/企业版） |
| 无运营后台 | 无全局视角 | 管理后台：租户/用量/系统健康监控 |
| AI 能力无价格锚点 | 智能问答免费无限用 | AI 调用次数计费，区分套餐额度 |
| 无注册/入驻流程 | 无用户自助入驻 | 注册 → 创建团队 → 14 天免费试用 → 付费 |

## 3. 商业模式设计

### 3.1 套餐分级

| 套餐 | 月费 | 仓库数 | 用户数 | AI 调用/月 | 报表 | 关键差异 |
|------|------|--------|--------|------------|------|----------|
| **免费版** | ¥0 | 1 | 3 | 100 | 基础 | 体验基础进销存 |
| **专业版** | ¥299/月 | 5 | 15 | 2,000 | 全部 | 小团队完整功能 |
| **企业版** | ¥999/月 | 20 | 50 | 10,000 | 全部 + 自定义 | 无限制 + 优先支持 |

> 价格仅为草案，上线前根据市场调研调整。

### 3.2 付费流

```
访问官网 → 注册 → 创建团队 → 14天免费试用（专业版权益）
  → 试用期结束前N天提醒
  → 到期后降级为免费版（仓库/用户/AI 降级，数据保留）
  → 用户随时可付费升级
  → 支付后即时开通（微信/支付宝/银行转账）
```

### 3.3 AI 计费模型

```
AI 调用次数 = DeepSeek API 请求次数（含 Function Calling 轮次）
  ├── 免费版：100 次/月（约每天 3 次）
  ├── 专业版：2,000 次/月（约每天 66 次）
  ├── 企业版：10,000 次/月（约每天 330 次）
  └── 超额：可购买附加包 ¥50/500 次
```

**AI 调用计数规则**：
- 每次用户发送消息 → 1 次调用
- 每次 Function Calling 执行 → 1 次额外调用（每个消息可能触发多次工具调用）
- System Prompt 注入不计
- 降级到 RuleAiProvider 不计

## 4. 功能范围

### 4.1 多租户架构

> **v1.1 已预埋 `tenant_id` 列，v2.0 正式启用。**

| 能力 | 说明 |
|------|------|
| 租户上下文 | 登录后注入 JWT → 全局 `RequestContext.tenantId` |
| MyBatis-Plus 拦截器 | 自动在所有查询中注入 `tenant_id = ?` 条件 |
| 管理端绕过 | 管理后台查询可绕过租户过滤（管理员视角全局数据） |
| 数据初始化 | 新租户注册后自动创建默认仓库、默认角色、演示数据 |
| 租户配置 | 每个租户独立的配置项（低库存阈值、备份策略等） |

**租户生命周期**：
```
注册 → active → [试用 → 付费] → [停用 → 30天冻结 → 删除]
```

### 4.2 多仓库管理

> **一个团队可管理多个物理仓库，每个仓库独立库存。**

| 能力 | 说明 |
|------|------|
| 仓库 CRUD | 管理员可创建/编辑仓库（名称、地址、联系人） |
| 仓库数据隔离 | 每个仓库独立库存、独立出入库、独立盘点 |
| 仓库切换 | 前端全局仓库选择器，切换后所有数据视图自动刷新 |
| 跨仓库调拨 | v2.0 不做——留到 v2.1 |
| 仓库级权限 | v2.0 不做——留到 v2.1 |

### 4.3 用户注册与团队入驻

| 能力 | 说明 |
|------|------|
| 注册页面 | 邮箱/手机号 + 密码注册（邮箱验证可选） |
| 创建团队 | 注册后引导创建团队（名称、行业、规模） |
| 团队角色 | 创建者 = Team Owner；可邀请成员（管理员/操作员/仓库员/客服） |
| 邀请成员 | 链接邀请或邮箱邀请（v2.0 手动创建账户，v2.1+ 自助注册加入） |
| 登录增强 | 支持邮箱 + 密码；可选微信扫码登录 |

### 4.4 订阅与计费

| 能力 | 说明 |
|------|------|
| 套餐管理 | 管理员可配置套餐（名称/价格/权益/状态） |
| 订阅记录 | 团队的订阅历史（开通/续费/升级/降级/取消） |
| 用量统计 | 仓库数、用户数、AI 调用次数（实时计数） |
| 用量限制 | 超过套餐上限阻止操作（如创建第 6 个仓库时提示升级） |
| 支付集成 | v2.0 第一阶段仅支持**人工支付确认**（上传付款凭证 → 管理员后台确认） |
| 到期提醒 | 到期前 7 天/3 天/1 天站内推送 + 邮件提醒 |

**不做什么（v2.0）**：
- 不做在线支付网关集成（留到 v2.1——先跑通人工支付流程验证商业模式）
- 不做发票自动化（留到 v2.1）
- 不做自动续费

### 4.5 管理后台

> **NovaDepot 运营团队视角的管理面板。**

| 模块 | 能力 |
|------|------|
| 租户管理 | 租户列表、启用/停用、套餐查看、数据量统计 |
| 用量监控 | 全局 AI 调用趋势图、活跃租户数、DAU |
| 系统健康 | 内存/CPU/Disk 使用率、DB 连接池、Redis 状态 |
| 套餐配置 | 套餐 CRUD、定价修改 |
| 订阅审核 | 支付确认、订阅手动开通 |

### 4.6 全局审计日志

| 能力 | 说明 |
|------|------|
| 管理后台审计 | 运营操作日志（手动开通订阅/停用租户/套餐修改） |
| 审计日志查询 | 按操作人/时间范围/操作类型筛选 |
| 数据导出 | CSV 导出审计日志 |
| 保留策略 | 360 天（vs 租户级 90 天） |

### 4.7 安全增强

| 能力 | 说明 |
|------|------|
| 密码策略 | 最小长度 8、复杂度可选、错误次数限制 |
| 登录保护 | 5 次失败锁定 15 分钟 |
| Token 刷新 | Access Token 30min + Refresh Token 7d |
| API 限流 | 按租户限流：免费版 60 req/min，专业版 300 req/min，企业版 1000 req/min |
| 数据导出限制 | 免费版不可导出 CSV，专业/企业版可导出 |
| IP 白名单 | 企业版可选（管理后台配置） |

### 4.8 体验优化

| 优化 | 说明 |
|------|------|
| 新手引导 | 首次登录后 Step-by-step 引导（创建产品 → 库存初始化 → 第一笔入库） |

## 8. 配置项

```yaml
# application.yml 新增/修改
app:
  tenant:
    default-plan: free                    # 新租户默认套餐
    trial-days: 14                        # 免费试用天数
    max-teams-per-tenant: 1               # v2.0 单租户单团队
  subscription:
    grace-days: 7                         # 到期后宽限期（数据保留但功能受限）
    remind-days: [7, 3, 1]               # 到期前提醒天数
  billing:
    payment-verification: manual          # 支付确认方式：manual（人工）/ auto（自动）
  ai:
    usage:
      free-limit: 100                     # 免费版 AI 月调用次数
      pro-limit: 2000                     # 专业版 AI 月调用次数
      enterprise-limit: 10000             # 企业版 AI 月调用次数
  security:
    login-max-attempts: 5                 # 登录失败上限
    login-lock-minutes: 15                # 锁定时间（分钟）
    password-min-length: 8
    rate-limit:
      free: 60                            # 免费版 req/min
      pro: 300                            # 专业版 req/min
      enterprise: 1000                    # 企业版 req/min
```

## 10. 验收标准

### 多租户
1. 不同团队的数据完全隔离（用户 A 看不到用户 B 的库存/订单）。
2. 新团队注册后自动初始化默认仓库和演示数据。
3. 管理后台可查看全局租户列表和用量。

### 多仓库
4. 一个团队可创建多个仓库，每个仓库独立库存/出入库/盘点。
5. 仓库选择器切换后页面数据正确刷新。

### 商业化
6. 免费版用户创建第 2 个仓库时被阻止并提示升级。
7. AI 调用超限后提示"本月额度已用完，请升级套餐"。
8. 到期后自动降级、宽限期内数据保留、过期后限制访问。

### 安全
9. 登录失败 5 次后被锁定 15 分钟。
10. API 限流按套餐级别正确执行。

### 管理后台
11. 管理后台可查看全局数据（租户/订阅/用量/系统健康）。
12. 运营人员可手动确认支付并开通订阅。

### 稳定性
13. 现有功能不受影响（E2E 全量通过）。
14. Docker 一键启动（含管理后台）。
15. 数据库迁移脚本可平滑升级。

## 11. 不做什么（严格）

1. 不做在线支付网关（微信/支付宝在线支付——留到 v2.1）。
2. 不做发票系统（留到 v2.1）。
3. 不做自动续费/自动扣款。
4. 不做跨仓库调拨。
5. 不做仓库级细粒度权限。
6. 不做多语言/国际化。
7. 不做开放 API / Webhook。
8. 不做官网 CMS / 博客 / 文档站（用静态站即可）。
9. 不做第三方登录（微信/钉钉/飞书扫码——留到 v2.1）。

## 12. 风险与应对

| 风险 | 应对 |
|------|------|
| 多租户数据隔离不彻底 | 所有集成测试覆盖租户隔离场景；TenantInterceptor 全局注入 |
| 既有数据迁移 tenant_id 回填复杂 | v1.1 已预埋 NULL 列，v2.0 只需配置拦截器 + 给默认租户回填 |
| 支付对接延迟 | v2.0 采用人工支付确认，避开支付网关集成复杂度 |
| 套餐定价不准确 | 先按草案上线，收集数据后 v2.1 调整 |
| AI 调用计数不准确 | 在 AiService 层统一计数，独立计数字段防并发 |
| 用户规模增长带来的 DB 压力 | v2.0 用户量级小（< 100 团队），单库可承载；v2.1+ 引入读写分离 |
| 免费版滥用（多账号薅羊毛） | 邮箱验证 + IP 限流 + 同一 IP 注册限制 |

### 回滚策略
- TenantInterceptor 可关闭（恢复单租户模式）。
- 多仓库可降级为单仓库。
- 计费/限制可关闭（全部免费）。
